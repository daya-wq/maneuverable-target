下面这版只实现到：

[
\boxed{\texttt{cooperative_future_tokens}\in\mathbb R^{B\times N\times H\times d}}
]

暂不实现位置、速度输出Head，也不实现运动学投影。上游意图预测器保持冻结，其GMM均值、方差和权重先由已经确定的GMM轨迹编码器处理。

同时对旧方案做一个关键精简：

> **Future Query不再重复查询三架无人机的全部 (3L) 个历史点。**

每架无人机的历史已经压缩进Agent token，队友信息又经过状态级三机注意力融合。重复查询全部历史会造成信息路径冗余，增加PPO训练和故障定位难度。

------

# 一、最终最小结构

```text
三架无人机历史状态 [B,N,L,F_hist]
        ↓
共享AgentHistoryEncoder
        ↓
agent_tokens [B,N,D]
history_tokens [B,N,L,D]     # 保留用于诊断，默认不再查询
        ↓
状态级Agent Interaction
        ↓
cooperative_agent_tokens [B,N,D]
        ↓
上一周期轨迹编码 [B,N,H,F_plan]
        ↓
建立N×H个Future Query
当前团队状态 + 未来时间 + 上一周期规划记忆
        ↓
时间对齐地查询3条GMM模式
        ↓
gmm_fused_queries [B,N,H,D]
        ↓
单机时间Self-Attention
        ↓
同一时刻三机Self-Attention
        ↓
FFN
        ↓
重复2层
        ↓
cooperative_future_tokens [B,N,H,D]
```

这套结构中：

- Agent token：总结过去；
- Future Query：表示未来输出槽位；
- GMM Cross-Attention：注入目标未来信息；
- Temporal Attention：协调同一架无人机的未来时间点；
- Future Agent Attention：协调三架无人机同一未来时刻的空间决策。

------

# 二、输入接口

## 1. 无人机历史状态

```python
agent_history: [B, N, L, F_hist]
agent_history_mask: [B, N, L] | None
```

其中：

- (B)：并行环境或batch数量；
- (N=3)：追捕无人机数量；
- (L)：历史窗口长度；
- (F_{\mathrm{hist}})：单帧状态维度。

建议每个历史状态包含：

```text
无人机相对目标的位置       3
无人机相对目标的速度       3
无人机自身加速度           3
```

第一版：

[
F_{\mathrm{hist}}=9
]

姿态、上一动作和跟踪误差暂时不要加入。等基础版本正常训练后再逐项消融。

------

## 2. 当前状态

```python
current_pos: [B, N, 3]
current_vel: [B, N, 3]
```

这里要求三架无人机处于同一个坐标系中。它们主要用于计算无人机间的关系特征：

[
\mathbf p_j-\mathbf p_i,\qquad
\mathbf v_j-\mathbf v_i
]

`current_acc`暂时不需要单独输入，因为最新加速度已经包含在 `agent_history` 最后一帧中。

------

## 3. 上一周期规划轨迹

```python
prev_plan: [B, N, H, F_plan]
prev_plan_mask: [B, N, H]
```

建议：

[
F_{\mathrm{plan}}=6
]

内容为：

```text
相对于当前真实位置的上一周期参考位置    3
上一周期参考速度                        3
```

注意：不能直接使用上一周期的旧世界坐标。每次重新规划前应当：

1. 删除已经执行的轨迹点；
2. 剩余轨迹相对于当前真实位置重新表达；
3. 补齐或重采样至长度 (H)；
4. 无效部分令 `prev_plan_mask=0`。

第一周期：

```python
prev_plan = torch.zeros(...)
prev_plan_mask = torch.zeros(...)
```

------

## 4. GMM编码结果

```python
gmm_mode_tokens:  [B, K, D]
gmm_point_tokens: [B, K, H, D]
gmm_weights:      [B, K]
gmm_log_weights:  [B, K]
```

其中：

[
K=3
]

要求Actor规划时域 (H) 与GMM预测点数量一致。若以后两者不同，必须先对GMM点token进行时间重采样，不能直接错位查询。

# 三、Agent历史编码器

## 1. 历史点编码

第 (i) 架无人机第 (\ell) 帧历史状态为：

[
\mathbf s_{i,\ell}\in\mathbb R^{F_{\mathrm{hist}}}
]

经过共享MLP：

# [ \mathbf e^{\mathrm{state}}_{i,\ell}

f_{\mathrm{hist}}(\mathbf s_{i,\ell})
\in\mathbb R^D
]

加入历史时间嵌入：

# [ \mathbf e^{\mathrm{hist}}_{i,\ell}

\mathbf e^{\mathrm{state}}*{i,\ell}
+
\mathbf e*\ell^{\mathrm{past}}
]

其中 (\mathbf e_\ell^{\mathrm{past}}) 表示该帧距离当前时刻有多远。

建议：

```python
self.history_point_encoder = nn.Sequential(
    nn.Linear(history_dim, d_model),
    nn.SiLU(),
    nn.Linear(d_model, d_model),
)

self.past_time_embedding = nn.Parameter(
    torch.randn(1, 1, history_len, d_model) * 0.02
)
```

------

## 2. `[AGENT]`摘要token

三架无人机共享一个可学习token：

```python
self.agent_token: [1, 1, 1, D]
```

对每架无人机形成序列：

[
[
\mathbf q^{\mathrm{agent}},
\mathbf e_{i,1}^{\mathrm{hist}},
\ldots,
\mathbf e_{i,L}^{\mathrm{hist}}
]
]

输入共享History Transformer：

# [ [ \mathbf a_i, \mathbf h_{i,1},\ldots,\mathbf h_{i,L} ]

\operatorname{HistoryEncoder}(\cdot)
]

其中：

- (\mathbf a_i)：整个历史的摘要；
- (\mathbf h_{i,\ell})：保留具体历史时刻的信息。

输出：

```python
agent_tokens:   [B, N, D]
history_tokens: [B, N, L, D]
```

第一版建议：

```python
d_model = 128
num_heads = 4
history_layers = 2
ff_dim = 256
dropout = 0.0
```

PPO策略网络中建议 `dropout=0.0`，避免采样阶段与更新阶段因随机Dropout导致log-prob不一致。

------

# 四、状态级三机交互

独立的 (\mathbf a_i) 只总结自身历史。需要通过三机交互使其获得当前团队状态。

## 1. 边特征

定义：

# [ \mathbf r_{ij}

\left[
\mathbf p_j-\mathbf p_i,;
\mathbf v_j-\mathbf v_i,;
|\mathbf p_j-\mathbf p_i|_2
\right]
\in\mathbb R^7
]

边特征只使用相对量，因此交换无人机编号时具有一致物理意义。

## 2. 带关系偏置的注意力

对每个注意力头：

# [ s_{ij}

\frac{
(\mathbf W_q\mathbf a_i)^\top
(\mathbf W_k\mathbf a_j)
}{
\sqrt{d_h}
}
+
b_{ij}
]

其中：

[
b_{ij}=f_{\mathrm{edge}}(\mathbf r_{ij})
]

表示无人机 (j) 对无人机 (i) 的当前相关程度。

归一化：

# [ \alpha_{ij}

\operatorname{softmax}*{j}(s*{ij})
]

更新：

# [ \bar{\mathbf a}_i

\operatorname{LayerNorm}
\left[
\mathbf a_i+
\sum_j\alpha_{ij}\mathbf W_v\mathbf a_j
\right]
]

输出：

```python
cooperative_agent_tokens: [B, N, D]
agent_attention: [B, num_heads, N, N]
```

这一步解决的是：

> 在开始规划未来之前，每架无人机知道队友当前处于什么状态。

不要添加固定的无人机编号Embedding。

------

# 五、上一周期规划记忆编码

上一周期每个轨迹点：

[
\mathbf P^{\mathrm{prev}}*{i,h}
\in\mathbb R^{F*{\mathrm{plan}}}
]

经过共享MLP：

# [ \mathbf e^{\mathrm{prev}}_{i,h}

f_{\mathrm{prev}}
\left(
\mathbf P^{\mathrm{prev}}_{i,h}
\right)
]

应用有效掩码：

# [ \tilde{\mathbf e}^{\mathrm{prev}}_{i,h}

m_{i,h}^{\mathrm{prev}}
\mathbf e^{\mathrm{prev}}_{i,h}
]

代码：

```python
prev_plan_tokens = self.prev_plan_encoder(prev_plan)

prev_plan_tokens = (
    prev_plan_tokens
    * prev_plan_mask.unsqueeze(-1).to(prev_plan_tokens.dtype)
)
```

建议再加入一个“是否有效”的Embedding，避免全零输入与真实零位置产生歧义：

```python
prev_plan_tokens = (
    prev_plan_tokens
    + self.prev_valid_embedding
      * prev_plan_mask.unsqueeze(-1)
)
```

输出：

```python
prev_plan_tokens: [B, N, H, D]
```

------

# 六、Future Query构造

每架无人机建立 (H) 个Future Query：

[
\mathbf q_{i,1}^{0},
\ldots,
\mathbf q_{i,H}^{0}
]

第 (h) 个Query定义为：

# [ \boxed{ \mathbf q_{i,h}^{0}

\mathbf W_a\bar{\mathbf a}*i
+
\mathbf e_h^{\mathrm{future}}
+
\mathbf W_p\tilde{\mathbf e}*{i,h}^{\mathrm{prev}}
}
]

分别表示：

- 当前自身与团队状态；
- 当前Query对应哪个未来时间；
- 上一周期在该时刻附近准备怎样运动。

代码：

```python
agent_base = self.agent_query_proj(
    cooperative_agent_tokens
).unsqueeze(2)
# [B, N, 1, D]

future_time = self.future_time_embedding[:, :, :H]
# [1, 1, H, D]

prev_context = self.prev_query_proj(prev_plan_tokens)
# [B, N, H, D]

queries = self.query_norm(
    agent_base + future_time + prev_context
)
```

输出：

```python
initial_future_queries: [B, N, H, D]
```

Future Query与Agent token不是同一个token：

- Agent token只有每架无人机一个；
- Future Query每架无人机有 (H) 个；
- Future Query由Agent token扩展而来，但通过未来时间和上一计划形成差异。

------

# 七、时间对齐的GMM Cross-Attention

## 1. 构造模式—时间上下文

第 (k) 条模式的整体token：

[
\mathbf m_k^{\mathrm{gmm}}
]

第 (h) 个轨迹点token：

[
\mathbf z_{k,h}^{\mathrm{gmm}}
]

融合为：

# [ \mathbf c_{k,h}^{\mathrm{gmm}}

\operatorname{LayerNorm}
\left(
\mathbf z_{k,h}^{\mathrm{gmm}}
+
\mathbf W_m\mathbf m_k^{\mathrm{gmm}}
\right)
]

代码：

```python
mode_context = self.gmm_context_norm(
    gmm_point_tokens
    + self.mode_to_point(gmm_mode_tokens).unsqueeze(2)
)
# [B, K, H, D]
```

------

## 2. 同一时刻查询三条模式

第 (i) 架无人机第 (h) 个Query，只查询：

[
{
\mathbf c_{1,h},
\mathbf c_{2,h},
\mathbf c_{3,h}
}
]

而不是查询全部 (K\times H) 个GMM点。这样可以保证时间严格对齐。

注意力分数：

# [ s_{i,h,k}

\frac{
(\mathbf W_q\mathbf q_{i,h})^\top
(\mathbf W_k\mathbf c_{k,h})
}{
\sqrt{d_h}
}
+
\lambda_\pi\log(\pi_k+\varepsilon)
]

其中：

- 第一项：无人机状态与目标模式的匹配程度；
- 第二项：GMM权重先验；
- (\lambda_\pi) 默认取0.5。

归一化：

# [ \beta_{i,h,k}

\operatorname{softmax}*{k}(s*{i,h,k})
]

GMM上下文：

# [ \mathbf g_{i,h}^{\mathrm{gmm}}

\sum_k
\beta_{i,h,k}
\mathbf W_v\mathbf c_{k,h}
]

残差更新：

# [ \mathbf q_{i,h}^{G}

\operatorname{LayerNorm}
\left(
\mathbf q_{i,h}^{0}
+
\mathbf g_{i,h}^{\mathrm{gmm}}
\right)
]

输出：

```python
gmm_fused_queries: [B, N, H, D]
gmm_attention:     [B, num_heads, N, H, K]
```

建议单独实现：

```python
class TimeAlignedGMMCrossAttention(nn.Module):
    ...
```

不要直接使用不带权重偏置的标准Cross-Attention封装。

------

# 八、删除默认History Cross-Attention

最小版本中不执行：

```text
Future Query → 查询全部3×L历史token
```

理由：

1. Agent token已经总结自己的历史；
2. Agent Interaction已经注入队友状态；
3. 上一周期轨迹明确提供未来记忆；
4. 再查询全部历史会导致重复路径。

`history_tokens`仍然保留在输出中，用于：

- 可视化；
- 单元测试；
- 后续消融实验。

配置中可以保留：

```python
use_self_history_cross_attention: bool = False
```

将来仅允许Query查询自己的 (L) 个历史token，不建议直接查询全部队友历史。

------

# 九、因子化协同解码器

GMM融合后得到：

```python
queries: [B, N, H, D]
```

每个协调Block只包含：

```text
Temporal Self-Attention
→ Future Agent Self-Attention
→ FFN
```

第一版重复2层，不建议直接使用3层。

------

## 1. 单机时间Self-Attention

固定无人机 (i)，取：

[
[
\mathbf q_{i,1},
\ldots,
\mathbf q_{i,H}
]
]

进行时间注意力：

# [ \mathbf Q_i'

\operatorname{TemporalAttention}(\mathbf Q_i)
]

实现时变形：

```python
x = queries.reshape(B * N, H, D)
x = self.temporal_attention(x)
queries = x.reshape(B, N, H, D)
```

不使用因果Mask，因为 (H) 个轨迹点是一次性联合规划，不是自回归生成。

作用：

- 让不同未来时刻交换信息；
- 形成完整轨迹意图；
- 防止各时刻token完全独立。

它不能保证物理平滑，真正的速度和加速度约束以后由输出Head和投影层处理。

------

## 2. 同一时刻三机Self-Attention

固定未来时刻 (h)，取：

[
[
\mathbf q_{1,h},
\mathbf q_{2,h},
\mathbf q_{3,h}
]
]

进行三机注意力：

# [ \mathbf Q_h'

\operatorname{FutureAgentAttention}(\mathbf Q_h)
]

实现时变形：

```python
x = queries.permute(0, 2, 1, 3)
# [B, H, N, D]

x = x.reshape(B * H, N, D)
x = self.future_agent_attention(x)
x = x.reshape(B, H, N, D)

queries = x.permute(0, 2, 1, 3)
# [B, N, H, D]
```

这一层交换的是三架无人机的**未来规划意图**，作用是：

- 知道队友在该时刻关注哪个目标模式；
- 避免三架无人机产生完全相同的未来表示；
- 学习同一时刻的同步围捕结构；
- 为后续位置与速度Head提供协同信息。

注意力本身不会自动产生分工，最终仍需要协同奖励。

------

## 3. FFN

每个token经过前馈网络：

# [ \operatorname{FFN}(\mathbf q)

\mathbf W_2
\operatorname{GELU}
(\mathbf W_1\mathbf q)
]

采用残差和LayerNorm。

------

## 4. 推荐Pre-Norm结构

每个Block：

```python
x = x + temporal_attn(norm_temporal(x))
x = x + future_agent_attn(norm_agent(x))
x = x + ffn(norm_ffn(x))
```

Pre-Norm通常比Post-Norm更适合深度RL训练。

```python
class AgentHistoryEncoder(nn.Module):
    """
    Input:
        agent_history:      [B, N, L, F_hist]
        agent_history_mask: [B, N, L] or None

    Output:
        agent_tokens:   [B, N, D]
        history_tokens: [B, N, L, D]
    """
class RelationalAgentInteraction(nn.Module):
    """
    Input:
        agent_tokens: [B, N, D]
        current_pos:  [B, N, 3]
        current_vel:  [B, N, 3]

    Output:
        cooperative_agent_tokens: [B, N, D]
        attention: [B, heads, N, N]
    """
class PreviousPlanEncoder(nn.Module):
    """
    Input:
        prev_plan:      [B, N, H, F_plan]
        prev_plan_mask: [B, N, H]

    Output:
        prev_plan_tokens: [B, N, H, D]
    """
class FutureQueryBuilder(nn.Module):
    """
    Input:
        cooperative_agent_tokens: [B, N, D]
        prev_plan_tokens:          [B, N, H, D]

    Output:
        future_queries: [B, N, H, D]
    """
class TimeAlignedGMMCrossAttention(nn.Module):
    """
    Input:
        queries:         [B, N, H, D]
        gmm_mode_tokens: [B, K, D]
        gmm_point_tokens:[B, K, H, D]
        gmm_log_weights: [B, K]

    Output:
        fused_queries: [B, N, H, D]
        attention:     [B, heads, N, H, K]
    """
class FactorizedCoordinationBlock(nn.Module):
    """
    Operations:
        Temporal Self-Attention over H
        Future-Agent Self-Attention over N
        FFN
    """
```

# 十一、总模块Forward流程

```python
def forward(...):
    if gmm_log_weights is None:
        weights = gmm_weights.clamp_min(self.cfg.eps)
        weights = weights / weights.sum(dim=-1, keepdim=True)
        gmm_log_weights = torch.log(weights)

    # 1. 历史编码
    hist_out = self.history_encoder(
        agent_history,
        agent_history_mask,
    )

    agent_tokens = hist_out["agent_tokens"]
    history_tokens = hist_out["history_tokens"]

    # 2. 当前状态级三机交互
    interaction_out = self.agent_interaction(
        agent_tokens,
        current_pos,
        current_vel,
    )

    cooperative_agent_tokens = (
        interaction_out["agent_tokens"]
    )

    # 3. 上一周期规划编码
    prev_plan_tokens = self.prev_plan_encoder(
        prev_plan,
        prev_plan_mask,
    )

    # 4. 建立Future Query
    initial_queries = self.query_builder(
        cooperative_agent_tokens,
        prev_plan_tokens,
    )

    # 5. 查询GMM
    gmm_out = self.gmm_cross_attention(
        initial_queries,
        gmm_mode_tokens,
        gmm_point_tokens,
        gmm_log_weights,
    )

    future_tokens = gmm_out["queries"]

    # 6. 时间和三机因子化协调
    temporal_attentions = []
    future_agent_attentions = []

    for block in self.coordination_blocks:
        block_out = block(future_tokens)
        future_tokens = block_out["tokens"]

        temporal_attentions.append(
            block_out["temporal_attention"]
        )
        future_agent_attentions.append(
            block_out["future_agent_attention"]
        )

    future_tokens = self.output_norm(future_tokens)

    return {
        "cooperative_future_tokens": future_tokens,

        "agent_tokens": agent_tokens,
        "history_tokens": history_tokens,
        "cooperative_agent_tokens": cooperative_agent_tokens,

        "initial_future_queries": initial_queries,
        "gmm_fused_queries": gmm_out["queries"],

        "agent_state_attention": interaction_out["attention"],
        "gmm_attention": gmm_out["attention"],
        "temporal_attention": temporal_attentions,
        "future_agent_attention": future_agent_attentions,
    }
```

## 3. GMM模式排列等变性

同时交换：

```text
gmm_mode_tokens
gmm_point_tokens
gmm_weights
gmm_log_weights
```

对应模式后，最终Future token应基本保持不变，GMM注意力的模式维应相应交换。

## 4. 上一计划Mask测试

当：

```python
prev_plan_mask.zero_()
```

改变 `prev_plan` 数值不应影响输出。

## 5. 时间敏感性测试

同一无人机不同未来时刻的Query不能完全相同：

```python
assert not torch.allclose(
    initial_queries[:, :, 0],
    initial_queries[:, :, -1],
)
```

## 6. 队友敏感性测试

固定无人机1自身历史，只改变无人机2状态。无人机1的：

```python
cooperative_agent_tokens[:, 0]
cooperative_future_tokens[:, 0]
```

应发生有限变化。

上游冻结的GMM预测器不得获得梯度。
