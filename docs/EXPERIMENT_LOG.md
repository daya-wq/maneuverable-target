## 2. 逐次记录

### E01 原始训练参数基线

- 日期：2026-10-16
- 目的：验证原配置在新轨迹Actor上的PPO更新稳定性。
- 配置：512环境，128步，16 mini-batch，2 epochs，Actor LR=`1e-4`，Critic LR=`5e-4`。
- 结果：rollout约3768 FPS；KL≈212.837；ratio clip fraction≈0.96875；策略在首轮更新内发生严重漂移。
- 结论：该学习率和重复epoch不适用于当前60维（10×6）轨迹动作分布。
- 日志：`results/smoke_512_one_update_20261016_r8.log`

### E02 大mini-batch显存测试

- 日期：2026-10-16
- 修改：512环境，mini-batch数由16降到8；每batch由4096增至8192环境时刻。
- 目的：减少每轮优化器步数，降低累计策略漂移。
- 结果：Actor反向传播OOM；当时约16.75 GiB已分配、18.35 GiB已保留，仅剩约166 MiB可用。
- 结论：当前24 GB RTX 4090不能稳定承载8192环境时刻的Actor反传；单batch以4096为实测安全上限。
- 日志：`results/sweep_512_mb8_ep1_lr1e5.log`

### E03 Actor LR=`1e-5`

- 日期：2026-10-16
- 配置：512环境，128步，16 mini-batch，1 epoch，Critic LR=`5e-4`。
- 目的：在4096单batch约束下寻找稳定学习率。
- 结果：KL≈0.04645；clip fraction≈0.591；ESS≈0.819；ratio范围约0.418–3.504。
- 结论：未崩溃，但仍远超期望KL范围，淘汰。
- 日志：`results/sweep_512_mb16_ep1_lr1e5.log`

### E04 Actor LR=`3e-6`单轮测试

- 日期：2026-10-16
- 配置：512环境，128步，16 mini-batch，1 epoch。
- 目的：进一步降低单次策略位移。
- 结果：KL≈0.004261；clip fraction≈0.180；ESS≈0.991；ratio范围约0.743–1.388；约3847 FPS。
- 结论：单轮稳定，但单轮结果不能证明后续rollout稳定。
- 日志：`results/sweep_512_mb16_ep1_lr3e6.log`

### E05 256环境对照

- 日期：2026-10-16
- 配置：256环境，128步，8 mini-batch，单batch仍为4096，Actor LR=`3e-6`。
- 目的：保持单batch大小不变，只比较环境数量和每轮优化器步数。
- 结果：约2519 FPS；KL≈0.00939；clip fraction≈0.366；ESS≈0.980；更新时间约1.74 s。
- 结论：256环境吞吐更低，首轮KL/clip也未优于512环境，不作为默认。
- 日志：`results/sweep_256_mb8_ep1_lr3e6.log`

### E06 修复前连续3轮，Actor LR=`3e-6`

- 日期：2026-10-17
- 配置：512环境，16 mini-batch，1 epoch，Actor LR=`3e-6`，Critic LR=`2e-4`，KL hard stop=0.02。
- 目的：检查单轮稳定参数在新策略继续采样后是否仍稳定。
- 结果：第1轮KL≈0.00426；第2轮KL≈0.04633且全部Actor更新被保护机制跳过；第3轮平均KL≈0.02028，约56% mini-batch被跳过。
- 结论：单轮结论不成立；KL保护有效，但存在跨rollout输入/概率不一致。
- 日志：`results/stability_512_3upd_lr3e6_critic2e4.log`

### E07 极低Actor LR排除实验

- 日期：2026-10-17
- 修改：Actor LR降至`1e-6`，Critic LR降至`1e-4`，其他保持不变。
- 目的：判断E06是否只是学习率过大。
- 结果：第1轮KL≈0.00079；第2轮仍出现KL≈0.04640、ratio max≈72.66，并全部跳过Actor更新；第3轮仍有31%更新被跳过。
- 结论：异常对Actor LR不敏感，根因不是常规超参数。
- 日志：`results/stability_512_3upd_lr1e6_critic1e4.log`

### C01 PPO观测快照修复

- 日期：2026-10-17
- 文件：`omni_drones/envs/hide_and_seek/hideandseek.py`
- 修改：`gmm_weights`、`strategic_probs`、`gmm_means`、`gmm_vars`由可变缓冲区的`expand`视图改为`detach + expand + clone`的逐步独立快照。
- 原因：环境每一步都会原地覆盖预测缓冲区。若rollout保存的是视图，训练时重新计算log-prob所见输入已不是采样动作时的输入，直接破坏PPO重要性比率。
- 同步清理：协同特征和按智能体扩展的奖励也物化为独立张量，消除TensorDict对expanded tensor写入的警告。
- 验证：见E08。

### E09 1024环境单卡容量测试

- 目的：判断1024环境是否会OOM，以及增加环境数能否改善样本吞吐。

### C02 目标高机动诊断

- 日期：2026-10-17
- 文件：`scripts/train.py`、`omni_drones/envs/hide_and_seek/hideandseek.py`、`docs/TENSORBOARD_METRICS_GUIDE.md`
- 目的：用真实状态而不是视频观感判断目标是否高机动。
- 新增指标：实际速度、指令/实际加速度、实际转向率、战略切换率、战术机动切换率、各模式占比。
- 结果：512环境三轮中，速度p95约3.00 m/s；实际加速度p95约3.29–3.47 m/s²；实际转向率p95约214–241 °/s；战术切换约3.67–3.73次/s；战略意图100%为模式2，切换率为0。
- 结论：高频急转成立；高过载和多战略覆盖不成立。当前目标最大速度固定3 m/s，并未逐episode随机变化。

### E11 1024环境单轮性能剖析

- 日期：2026-10-17
- 配置：与E09完全一致；仅增加C03分阶段计时，不改训练参数。
- 待验证假设：数分钟额外开销来自目标机动统计或episode统计，而不是PPO网络更新。
- 结果：rollout 26.43 s；目标机动统计0.0037 s；episode统计295.27 s；预测器+Actor+Critic更新6.66 s；后处理与更新合计301.94 s；完整update 328.39 s。
- 结论：瓶颈唯一集中在`EpisodeStats`。旧实现把约3000个终止episode拆成数千个独立TensorDict对象，再由Python逐对象堆叠；网络和高机动诊断不是瓶颈。

- 结果：

### C05 目标能力逐episode随机化、战略阈值修正与显式越界终止

- 日期：2026-10-17
- 文件：`cfg/task/HideAndSeek.yaml`、`omni_drones/envs/hide_and_seek/hideandseek.py`、`scripts/train.py`、`docs/STRATEGIC_MODES_AND_ARENA.md`、`docs/TENSORBOARD_METRICS_GUIDE.md`
- 修改内容：目标最大速度和最大加速度在每个并行环境的每个episode分别独立采样3.0–3.5；初始速度大小采样0.5–3.0，水平航向全向随机、俯仰方向在±15°内随机；目标位置继续按既有front-box范围逐episode随机；能力上限不进入Actor观测。
- 战略修正：`target_tactical_far_distance`由10.5 m改为6.0 m，保留守区冲刺阈值1.0 m。旧阈值几乎覆盖半径6 m的整个场地，是`GOAL_PRIORITY`标签退化的主要原因。
