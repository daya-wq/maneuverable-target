### GMM 方差接入

OT 粒子权重现在使用 GMM 方差置信度调制：

```text
confidence_k = exp(-variance_weight_scale * mean_std_k)
confidence_k = max(confidence_k, variance_weight_floor)
mode_weight_k ∝ gmm_weight_k * confidence_k
```

低方差轨迹分支会获得更高决策权重，高方差分支通过 floor 保留为不确定性覆盖。

## 结论

`success` 和 `goal_reached` 在单个 episode 终止语义上是互斥的：环境代码中 `capture_before_goal = capture_done & ~goal_reached & ~any_landed & ~drone_collision_done`，`done = timeout | capture_before_goal | goal_reached | any_landed | drone_collision_done`。训练日志里二者同时偏高，主要是旧 stats 口径容易被 collector/reset 后的 sticky episode stats 误导，不代表同一 episode 同时成功又进守区。

我用 final checkpoint 做了独立 deterministic 几何评估，按 done 当步位置重新判定终止原因：

- `capture`: 23 / 32
- `goal`: 1 / 32
- `drone_collision`: 4 / 32
- `timeout_or_other`: 4 / 32
- `stats_success_count`: 23 / 32
- `stats_goal_count`: 1 / 32
- `stats_success_and_goal_overlap`: 0 / 32

因此当前策略不是“成功和目标进守区都很多”，而是“捕获率已经有，但队形/高度/终端封堵不稳”。

## SO3/六自由度执行确认

当前目标和追捕方都不是点质量执行。目标使用 `target_dynamics_mode: uav`，追捕方使用 Crazyflie multirotor 模型。

追捕方执行链路：

```text
RL actor 输出 a_residual_norm ∈ [-1,1]^3
residual = a_residual_norm * ot_residual_accel_limit
a_cmd = clip_norm(a_ot + residual, pursuer_accel_limit)
thrust_world = a_cmd + 9.81 * e3
z_des = normalize(thrust_world)
SO3 attitude error -> omega_body
PIDRateController(target_rate, target_thrust)
drone.apply_action(cmds)
```

目标执行链路：

```text
APF/意图力 -> desired_vel/feedforward_acc
velocity error -> desired_acc
desired_acc -> thrust_world/z_des/omega_body/thrust
PIDRateController
target.apply_action(cmds)
```

所以当前问题不是“没有接入六自由度/SO3”，而是在六自由度约束下，OT/RL 生成的参考和奖励还没有形成稳定队形、高度安全和终端封堵。

## 主要问题

1. 旧 `success/goal_reached` stats 容易误读。

已新增互斥终止诊断字段：

```text
terminal_capture
terminal_goal
terminal_floor_collision
terminal_landed
terminal_drone_collision
terminal_timeout
```

下一次训练请优先看这些字段，而不是只看 sticky 的 `success/goal_reached`。

2. `Close_Evade` 战略概率严重塌缩。

独立评估均值 `Close_Evade≈0.933`，`Goal_Priority/Goal_Sprint` 基本没接管终端守区。这会导致 OT 密度长期偏侧向展开，而不是在目标接近守区时强堵入口。

## 下一轮最小修改建议

已把最小建议整理成当前训练入口，不再一次性追加大改：

1. 终止/统计口径。

保留新增 `terminal_*` 字段；下一轮训练用它判断真实成功率。`terminal_floor_collision` 已经纳入 done 和评估脚本，后续重点看它是否随 OT-only / residual 学习下降。

2. 速度和物理口径。

目标和追捕方最大速度都锁到 `3.0m/s`；`v_prey=1.0` 表示目标速度等于追捕方速度。显式设置 `target_physics_max_velocity=3.0`，避免目标 UAV 物理层瞬时超过指令速度上限。

3. 提高终端封堵和战略切换权重。

将目标接近守区时的 pseudo-label 或 predictor loss 做 class balance，让 `Goal_Priority/Goal_Sprint` 在 `goal_dist` 小时能接管。可先不改网络结构，只调整 label/采样权重和 `ot_line_coef`。

4. 增加终端队形分离。

5. 收紧高度安全。

`collision_floor` 已经变成 done 并进入强终止语义；下一步建议从 scratch 重训，因为旧 final checkpoint 可能带着已经学到的近地/触地习惯。

6. 下一次训练入口。

当前已经加入 floor done、目标最优机动、目标动力增强和预测方差权重，因此建议 restart-scratch，因为任务语义已经改变。

## 2026-06-17 近距高机动目标修正

用户指出轨迹仍像直线目标，这个判断是对的。根因不是 SO3 执行端，而是目标机动决策端：

1. `target_tactical_far_distance=6.0`，而初始追逃距离约 `9-10.5m`，导致目标大部分早期时间仍按 `Far_Rush` 直冲守区。

2. 近距虽然进入了 `_select_target_optimal_maneuver_force`，但旧版本只用 `dt=0.01s` 做一步前瞻。横向/垂向机动在 0.01 秒内几乎不能提升追捕距离，反而降低守区推进，因此效用函数偏向继续直飞。

3. 旧效用中 `target_opt_maneuver_goal_weight=4.0`、`target_maneuver_force_coef=0.9`，守区推进过强、机动力过弱，导致 Close_Evade/Goal_Priority 在视觉上仍很平滑。

已修改：

1. 近距威胁触发提前到 `target_tactical_far_distance=10.5`，目标从初始约 10m 就开始进入威胁感知。

2. 目标候选机动从一步贪心改为 `10 x 0.05s = 0.5s` 前瞻，并用追捕方当前速度预测未来收口位置。

3. 效用函数改为：未来最小追捕距离 + 守区推进 + 横向展开 + 转向强度 - 高度/边界惩罚。

4. 目标机动参数调整为更偏横向对抗：`target_maneuver_force_coef=2.2`、`target_maneuver_forward_scale=0.15`、`target_maneuver_vertical_scale=0.65`。

5. 评估脚本新增真实 `target_tactical_intent` 和 `target_maneuver_id` 记录，图中黑色虚线为真实战术，紫色点线为机动编号。
