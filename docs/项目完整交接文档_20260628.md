# 高机动目标追捕项目完整交接文档

生成时间：2026-06-28  
当前主线：`OT-guided residual MARL`，即“战略意图 + GMM轨迹预测 -> OT拦截布局 -> RL残差加速度 -> SO3/PIDRate执行”。

## 0. 一句话理解这个项目

本项目要解决的不是直线目标追捕，而是三架 6DoF 追捕无人机对一个高机动 6DoF 目标无人机的协同拦截问题。核心思想是：先预测目标未来多模态轨迹和战略意图，再用最优传输把三个追捕方提前布到最有价值的拦截参考点，最后让 MARL 只学习 OT 基准控制之外的残差动作。

当前代码中，旧 Expert2 固定角色分配、TP_net 单点预测、专家监督 imitation/Expert-KL 都不属于新方法主链路。

## 1. 目标无人机目前的具体机动

### 1.1 目标动力学与全局参数

目标控制链路是：

```text
APF/最优机动力 -> desired_acc -> target_vel_cmd -> SO3期望姿态/推力 -> PIDRate(T,w) -> target.apply_action()
```

### 1.2 战略意图定义

当前战略意图固定为 4 类：

| ID | 名称 | 触发条件 | 行为侧重 |
|---:|---|---|---|
| 0 | `Far_Rush` | 未进入近距，且不在终端冲刺 | 主要向守区直冲 |
| 1 | `Close_Evade` | 最近追捕方距离小于 `10.5 m`，且目标到守区距离大于最近追捕方距离 | 在保持去守区趋势的同时主动规避追捕方 |
| 2 | `Goal_Priority` | 近距，且目标到守区距离小于等于最近追捕方距离 | 强化守区优先，但仍保留规避 |
| 3 | `Goal_Sprint` | 到守区距离小于 `1.0 m` | 终端冲刺进守区 |

一个非常重要的现实影响：当前初始距离约 `9.0-10.5 m`，而 `target_tactical_far_distance=10.5`，所以训练/评估一开始目标就很容易进入 `Close_Evade` 或 `Goal_Priority`。这会导致 `Far_Rush` 真实样本占比很低，甚至在部分评估里为 0。

### 1.3 目标受力构成

目标每步先计算：

```text
force = boundary_force + strategic_goal_force + repulsion_force + optimal_maneuver_force
desired_acc = target_accel_limit * normalize(force)
```

不同战略意图下的力：

| 战略意图 | 目标吸引 | 追捕方排斥 | 最优机动 |
|---|---:|---:|---|
| `Far_Rush` | `1.0 * goal_force` | 无主动排斥 | 无 |
| `Close_Evade` | `1.0 * goal_force` | `2.4 * nearest + 1.3 * others` | 有 |
| `Goal_Priority` | `1.8 * goal_force` | `0.8 * (2.4 * nearest + 1.3 * others)` | 有 |
| `Goal_Sprint` | `1.25 * goal_force` | `0.7 * (2.4 * nearest + 1.3 * others)` | 有 |

边界力一直存在，用于避免出界、过高、低于目标最小高度。

### 1.4 近距最优机动候选

当前不是旧随机 9 类机动。近距时目标会在 9 个候选中按 0.5s 预估收益选择最优动作。

候选基向量：

| 分量 | 当前系数 |
|---|---:|
| 前向分量 | `target_maneuver_force_coef * forward_scale = 2.2 * 0.15 = 0.33` |
| 侧向分量 | `target_maneuver_force_coef = 2.2` |
| 垂向分量 | `target_maneuver_force_coef * vertical_scale = 2.2 * 0.65 = 1.43` |
| 低速方向阈值 | `0.3 m/s`，低于该值用守区方向作为 forward |

9 个候选：

| ID | 机动 |
|---:|---|
| 0 | forward |
| 1 | left |
| 2 | right |
| 3 | up |
| 4 | down |
| 5 | left_up |
| 6 | left_down |
| 7 | right_up |
| 8 | right_down |

每个候选会向前模拟：

| 项 | 当前值 |
|---|---:|
| lookahead steps | `10` |
| lookahead dt | `0.05 s` |
| 总预测窗口 | `0.5 s` |
| 速度截断 | `3.0 m/s` |
| 加速度截断 | `3.5 m/s^2` |

候选得分：

```text
utility =
  2.0 * min_pursuer_dist
+ 3.0 * goal_progress
+ 0.55 * lateral_disp
+ 0.35 * turn_score
- 4.0 * height_penalty
- 3.0 * boundary_penalty
```

这里的含义是：目标同时追求“离追捕方远”“更接近守区”“有侧向展开和转向”“不穿地、不越界”。当前选择是每步更新，`target_maneuver_timer` 在新逻辑里基本只作为诊断字段，不再决定随机机动持续时间。

### 1.5 为什么轨迹看起来可能仍然平滑

即使目标已经不是直线，视觉上仍可能显得不够“高对抗”，原因主要有四个：

- 目标速度和追捕方同为 `3.0 m/s`，目标优势主要来自加速度和策略，不是速度压制。
- 目标实际经过 `target_vel_cmd` 和 SO3/PIDRate 执行，6DoF 动力学、倾角限制、速度阻尼会自然平滑轨迹。
- 当前 utility 中 `goal_progress` 权重为 `3.0`，会持续拉目标向守区，可能压制部分横向/垂向机动视觉效果。
- 初始几何离守区较远且近距阈值大，目标经常处于 `Goal_Priority`，它会比纯 `Close_Evade` 更偏向守区入口。

因此，后续判断“高机动”不能只看肉眼轨迹，应补充曲率、横向加速度、转弯角速度、jerk、机动候选占比这些指标。

```text

  -> weight_head -> gmm_weights

```

### 2.3 决策模块：OT-guided residual MARL

当前决策主线：

```text
战略意图概率 + GMM轨迹 -> 离散拦截密度 -> Sinkhorn OT -> 三个参考拦截点
-> OT基准加速度 -> RL残差加速度 -> SO3/PIDRate -> drone.apply_action()
```

#### 预测频率与执行频率

这里一定要区分两个频率：

| 链路 | 当前频率逻辑 |
|---|---|
| 预测/OT 参考更新 | 每 `dt_pred=0.05s` 更新一次，代码里用 `ot_prediction_stride = round(dt_pred / sim_dt)` 对齐仿真步 |
| 追捕方执行 | 每个仿真 step 都执行 `drone.apply_action()` |
| 两者衔接 | 非预测更新步复用缓存的 `b_i/b_dot_i`，但会用当前追捕方位置速度重新计算 OT 基准加速度 |

因此不是“每 0.05s 才控制一次无人机”。实际执行端仍按仿真步持续闭环，只是预测器和 OT 参考点按 0.05s 节奏刷新。

#### OT 拦截密度构造

输入：

```text
pursuer_pos:      [B, 3, 3]
pursuer_vel:      [B, 3, 3]
target_pos:       [B, 3]
target_vel:       [B, 3]
goal_pos:         [B, 3]
strategic_probs:  [B, 4]
gmm_weights:      [B, 3]
gmm_means_world:  [B, 3, 10, 3]
gmm_vars:         [B, 3, 10, 3]
```

离散粒子构造：

| 粒子来源 | 数量 | 含义 |
|---|---:|---|
| GMM 轨迹前移粒子 | `3 * 10 = 30` | 未来目标点沿目标-守区方向前移 `block_distance=0.45` |
| 守区通道粒子 | `3 * 3 = 9` | 近、中、入口三个通道截面，每个截面中心/左/右 |
| 近距侧向封堵粒子 | `2` | `Close_Evade` 时左右侧向封堵 |
| 总粒子数 | `41` | Sinkhorn 的列端密度 |

权重构造：

- GMM 分量权重会乘方差置信度，低方差分量权重大，高方差分量保留 `variance_weight_floor=0.10`。
- `Far_Rush`、`Goal_Priority`、`Goal_Sprint` 会增强守区通道粒子。
- `Close_Evade` 会增强轨迹粒子和左右封堵粒子。
- 粒子 z 高度设置动态地面兼容下限，正常不低于 `min_ref_z=0.90`，但如果目标很低，参考点允许降到 `target_z - 0.10`，最低 `hard_floor_z=0.30`。

#### Sinkhorn OT

参数：

| 项 | 当前值 |
|---|---:|
| Sinkhorn iters | 24 |
| epsilon | 2.0 |
| row marginal | 每架追捕方 `1/3` |

#### RL 动作与执行端

追捕方 actor 输出：

```text
action: [num_envs, 3 agents, 3]
```

含义是归一化残差加速度：

```text
a_residual = clamp(action, -1, 1) * residual_accel_limit * residual_warmup_scale
a_cmd = clip(a_ot + a_residual, pursuer_accel_limit)
```

执行端：

```text
a_cmd
  -> 地面 barrier 修正
  -> 水平/垂直加速度限幅
  -> SO3: thrust_world = a_cmd + g * e3
  -> desired body z
  -> body rate omega_body
  -> normalized [wx, wy, wz, thrust]
  -> PIDRateController
  -> drone.apply_action()
```

这里追捕方和目标都是 6DoF 非线性模型，不是直接设置位置或速度。

#### Actor/Critic 网络

算法配置：`cfg/algo/mappo.yaml`

Actor：

- MAPPO，`share_actor: true`。
- 输入为每个 agent 的局部观测字典。
- 编码器为 `CoopEntityAttentionEncoder`。
- self token 由 `state_self + cooperation` 线性映射到 128 维。
- teammate token 由 `state_others` 线性映射到 128 维。
- 2 层 TransformerEncoder，4 heads，FFN 256，GELU。
- 输出 self token 表征，接 `TanhIndependentNormalModule`。
- `log_std_init=-1.0`，范围 `[-3.0, 0.0]`。
- 无 RNN，BC auxiliary 关闭。

Critic：

- `critic_input: state`，集中式训练。
- `state_drones` 为每架无人机的 `state_self + cooperation`。
- 编码器为 `RelationEncoder`。
- 对所有 agent pair 做关系嵌入聚合，再输出 value。
- value normalization 开启，Huber loss 开启。

## 5. 当前存在的问题

### 5.1 目标高机动的“可见性”仍不足

代码层面目标已经有近距最优机动，但轨迹图上有时仍显得平滑。主要原因是 6DoF 控制链路和速度上限会把机动平滑化，且当前 utility 仍强推守区进展。

建议补充指标：

- 目标曲率均值和峰值。
- 横向加速度占比。
- yaw/heading 转向速率。
- jerk。
- 9 个候选机动的时间占比。
- Close_Evade 阶段单独轨迹图。

### 5.2 Far_Rush 样本严重不足

OT-only 评估中 `true_frac_Far_Rush=0.0`。这不是预测器一定坍塌，而是当前 reset 初始距离和 `target_tactical_far_distance=10.5` 让目标开局就处于近距战略。若论文需要完整四类战略变化，需要重新设计初始距离分布或降低 far threshold。

### 5.3 OT-only 能接近但不能捕获

OT-only 最小目标距离均值约 `0.577 m`，捕获半径是 `0.4 m`，说明差“最后一口”。这类失败不是预测完全错，而是拦截参考点、SO3跟踪和终端包围几何还不够强。

### 5.4 RL 残差尚未显著提升最终收口

最新 scratch 训练 capture 约 26.6%，但 timeout 45.3%、drone collision 17.2%。残差已经开始学习，但没有稳定学出“最后闭合”和“互相避让”。

### 5.5 三机互撞/收口拥挤仍明显

`terminal_drone_collision=0.171875`，`pursuer_collisions_count=2.1875`。这说明当前 OT 参考点的最小间距、侧向槽位、终端收口策略仍不够稳。已经有 `ref_min_separation=0.85` 和 separation projection，但实际闭环跟踪时仍会拥挤。

### 5.6 部分 stats 是累计量，不能直接当概率

例如训练日志里 `strategic_goal_priority` 和 `ot_residual_scale` 可能大于 1，这是因为环境用 `stats.add_()` 按 episode 累积，不是所有字段都做了时间归一。判断战略占比应优先看专门的 trajectory summary，或重新写规范化 logger。

### 5.7 `goal_reached` 容易误导

之前已经修过 terminal cause 的互斥统计。现在应优先看：

```text
terminal_capture
terminal_goal
terminal_drone_collision
terminal_floor_collision
terminal_timeout
```

不要单独用 `goal_reached` 判断最终失败率，因为它可能是 episode 内曾经接近/触发过的累计标志。

### 5.8 预测器在线版本仍弱于历史离线报告

当前 RL 联合训练末尾：

```text
predictor_minADE ~= 0.385 m
predictor_FDE ~= 0.804 m
strategic_accuracy ~= 0.777
```

历史离线 1.0s 报告：

```text
ADE ~= 0.221 m
FDE ~= 0.503 m
strategic_accuracy ~= 0.880
```

两者窗口、数据分布、训练方式都不同，不能直接等价比较。但在线预测器仍需要更强的监督数据和更稳定的联合训练。

## 6. 后续建议优先级

### P0：先把评估闭环标准化

- 每次训练后跑同一个 eval 脚本，保存 3D 轨迹、CSV、事件统计。
- 统一报告 terminal cause，不再使用模糊的 success/goal_reached 单指标。
- 对 Close_Evade、Goal_Priority、Goal_Sprint 分战略分别画轨迹。

### P1：先评估 OT，再评估 RL 残差

建议固定同一批种子做三组：

| 组 | 设置 | 目的 |
|---|---|---|
| Kinematic fallback + OT-only | residual=0，无预测器 | 看几何布局本身是否合理 |
| Strategic GMM + OT-only | residual=0，有预测器 | 看预测是否改善布局 |
| Strategic GMM + OT + RL residual | 正常训练策略 | 看残差是否真的补足终端收口 |

只有第三组超过第二组，才能说明 RL 残差真正有贡献。

### P2：提升目标高机动可见性

如果目标仍显得不够高对抗，优先改 utility，而不是只提高速度：

- 降低 `target_opt_maneuver_goal_weight`，让 Close_Evade 更愿意横向/垂向脱离。
- 提高 `target_opt_maneuver_lateral_weight` 和 `target_opt_maneuver_turn_weight`。
- 对 Close_Evade 单独提高侧向候选权重。
- 增加目标机动指标约束，确保“高机动”是可量化的。

### P3：改善 OT 终端收口

- 针对距离目标小于 1m 的终端阶段，动态增大 lateral spread，避免三机同向挤压。
- 对 barycenter 加入更强的互斥或最小夹角约束。
- 将捕获半径附近的 OT 密度从“守区通道”切换为“目标局部包围壳”。
- 对每个追捕方加入可达性约束，避免分配到需要瞬时大转弯的参考点。

### P4：改善在线预测器

- 用当前高机动目标重新生成 0.5s 输入/0.5s 输出数据集。
- 离线预训练当前 `StrategicGMMTrajectoryPredictor`，再放入 RL 联合训练。
- 对战略类别做分布均衡，尤其补 `Far_Rush`。
- 在 GMM 权重中继续使用方差置信度，但需要记录每个 mode 的 NLL/minADE，避免 GMM 坍塌。

## 8. 交接时最容易混淆的点

- `v_prey=1.0` 是乘子，目标最大速度仍是 `3 m/s`。
- 历史报告的 1.0s 预测网络不是当前 RL 主线的 0.5s 在线预测器。

- OT-only 和 RL-residual 必须分开评估，否则无法证明残差是否有贡献。

## 9. 当前方法的论文表达重点

可以讲的创新点：

- 用战略意图条件化的多模态轨迹预测，不是只预测单点目标位置。
- 把未来轨迹分布转成时变拦截密度，再通过离散 OT 生成三机协同拦截参考点。
- RL 不从零学习完整控制，而是学习 OT 基准上的残差加速度，提高工程可控性。
- 决策输出仍经过 SO3/PIDRate 执行，兼顾 6DoF 非线性动力学和可落地控制接口。
- 根据不同战略意图连续调制拦截密度：Far_Rush 强守区通道，Close_Evade 强侧向覆盖，Goal_Priority/Goal_Sprint 强终端入口封堵。

当前还不能过度声称的点：

- 不能声称成功率已经稳定很高，最新 scratch 训练只有约 26.6% terminal capture。
- 不能声称 RL 残差已经显著优于 OT-only，仍需要同种子对比评估。
- 不能声称四类战略都充分训练，当前 Far_Rush 样本明显不足。
- 不能只凭肉眼轨迹说目标高机动，必须补量化机动指标。
