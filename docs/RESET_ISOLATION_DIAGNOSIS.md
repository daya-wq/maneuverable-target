# 部分环境复位干扰其他无人机：定位与修复

日期：2026-10-22 05:40–05:55，北京时间。

## 结论

训练采样器没有偷偷换成随机策略。真正发现的干扰是：一个环境结束时，`_reset_idx`会额外执行一次全局`sim.step`。这不仅推进要复位的无人机，也推进仍在追捕的其他环境，而且没有完整执行100 Hz控制、轨迹采样和规划步计数。并行环境越多、结束越频繁，这种干扰越明显。

这解释了训练与独立评测差异的重要来源，但不证明它是所有学习失败的唯一原因。修复后旧模型仍不抓捕，且真实升高越界重新显现，不能把“训练统计看起来更安全”当作性能提升。

## 修改了什么

1. `HideAndSeek70Isolated`继承Consistent配置，仅用`reset_profile.advance_physics_on_reset=false`关闭复位时的全局物理推进。重置选定机体状态后仍使用IsaacEnv已有的flush同步；不是冻结正常的100 Hz物理执行。
2. 历史轨迹增加每环境规划步时钟。同一个规划步内重复读取观测不再重复插入历史；部分复位只初始化被复位的环境，其他环境仍保持0.05秒的历史点间隔。
3. 原70/V2/Consistent默认保留旧复位方式以复现实验。新旧参数和物理条件不能混称同一条曲线；新尝试单独计数。
4. 不扩大推力，不覆盖无人机位置/速度，不改抓捕半径或放宽目标速度，不引入规则教师来冒充PPO。

原训练的`episode_duration_s=规划步数×0.05`不包含额外复位物理步，因而旧训练中该值不能严格当作完整物理经过时间。修复后正常步进与轨迹采样重新一致；旧独立评测首局不执行部分复位，不能直接与旧训练的时钟等同。
