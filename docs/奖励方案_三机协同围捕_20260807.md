# 三机协同围捕 — Actor轨迹输出 + Minimum Snap 奖励方案设计

> 日期：2026-08-07  
> 背景：Actor 输出 H=10, dt=0.05s 的航路点 → minimum snap 生成轨迹 → 底层控制器执行 0.05s  
> 核心挑战：三架无人机不扎堆、不追尾、具有"先知能力"提前围堵

---

## 0. 设计目标

当前主线直接使用目标的多模态未来预测和三机协同状态产生未来航路点。奖励只负责评价追捕进展、安全、控制平滑度和终端结果，不再生成或分配追捕参考点。

重点解决三个问题：
1. **前瞻性**：基于目标未来轨迹评价拦截质量，而不是只追逐当前位置。
2. **协同性**：三机利用共享未来信息形成互补航路，避免扎堆。
3. **可执行性**：策略输出的航路点经过轨迹与底层控制约束后能够稳定执行。

---

## 1. 奖励设计总体框架

```text
                     ┌─ R_intercept:   前瞻拦截奖励 (核心)
                     ├─ R_encircle:    角度包围奖励 (防扎堆)
  R_total = Σ w_i ·  ├─ R_mode_cover:  模式覆盖奖励 (各司其职)
                     ├─ R_block:       目标-球门拦截奖励
                     ├─ R_smooth:      轨迹平滑奖励 (配合 min snap)
                     ├─ R_sep:         安全分离奖励
                     ├─ R_early:       尽早拦截奖励
                     └─ R_terminal:    终端事件 (捕获/球门/碰撞/超时)
```

**设计铁律**：所有空间类奖励基于**目标预测未来位置**，而非当前位置。

---

## 2. 各奖励项详细设计

### 2.1 R_intercept — 前瞻拦截奖励 ⭐ 核心

**含义**：奖励无人机轨迹与目标预测轨迹的**最小空间距离**。

**为什么越高越好**：越高 → drone 的轨迹越接近目标未来会经过的位置 → 具有"先知"能力。

**数学定义**：

```
给定:
  drone_traj_i = [p_{i,1}, p_{i,2}, ..., p_{i,H}]      drone i 的未来航路点
  target_pred   = [μ_{h}]_{h=1..T_pred}                 目标预测轨迹 (取 GMM 最高权重模式)

d_min,i = min_{h1∈[1,H], h2∈[1,T_pred]} || p_{i,h1} - μ_{h2} ||

R_intercept,i = exp(-d_min,i / σ_intercept)
```

**关键**：取 min over drone 时步 AND target 时步 → 不要求时间对齐，只要求空间覆盖。drone 只要在**任意未来时刻**靠近目标的**任意预测位置**，就能获得奖励。

**σ_intercept**：控制奖励的空间敏感度。建议 0.5m（半米内满分，1m 外迅速衰减）。

**为什么这样设计**：
- 时间解耦：drone 不需要精确匹配目标到达某位置的时刻，只要占据了那个空间即可
- 这天然鼓励 drone 提前到达目标可能去的位置进行"蹲守"
- 如果 drone 只能到达目标当前所在位置，则 `d_min` 较大，奖励低

---

### 2.2 R_encircle — 角度包围奖励 ⭐ 防扎堆

**含义**：奖励三架无人机在目标预测位置周围形成**均匀角度分布**。

**为什么越高越好**：越高 → 三机从不同方向围堵 → 目标无论向哪个方向逃逸都有 drone 拦截 → 真正的协同围捕。

**数学定义**：

```
给定:
  目标预测质心: target_center = mean_k(mean_h(gmm_means_{k,h}))
  或取 GMM 最高权重模式的中间时刻位置

对每个 drone i:
  θ_i = atan2(p_{i,mid}.y - target_center.y, p_{i,mid}.x - target_center.x)  ∈ [0, 2π)

将 θ_1, θ_2, θ_3 排序:
  θ_(1) ≤ θ_(2) ≤ θ_(3)

角度间隔:
  g_1 = θ_(2) - θ_(1)
  g_2 = θ_(3) - θ_(2)  
  g_3 = 2π - (θ_(3) - θ_(1))

最大间隔: g_max = max(g_1, g_2, g_3)

R_encircle = 1 - g_max / (2π)
```

**数值示例**：

| 场景 | g_max | R_encircle |
|---|---|---|
| 完美三角包围 (120°×3) | 120° (2π/3) | **0.667** |
| 两机在一起 + 一机对面 | 180° | 0.500 |
| 三机成 90° 扇形 | 270° | 0.250 |
| 三机挤在同一方向 | 360° (2π) | **0.000** |

**为什么这样设计**：
- 只奖励角度分散，不惩罚距离（距离由 R_intercept 负责）
- 最大值 0.667（非 1.0）意味着训练信号始终存在改进空间
- 使用 max gap 而非方差：方差对 outlier 不敏感（两个 drone 挤在一起，一个在远处，方差可能看起来还 OK），max gap 直接抓住了"漏风"方向

**注意**：需要先判断 drone 是否在目标附近（d_min < 阈值），否则远处的 drone 的角度无意义。设置：

```python
R_encircle = R_encircle * (d_min < encircle_range).float()  # encircle_range = 2.0m
```

---

### 2.3 R_mode_cover — 模式覆盖奖励

**含义**：奖励三架无人机**各自覆盖不同的 GMM 预测模式**。

**为什么越高越好**：GMM 的 K=3 个模式代表目标的 3 种可能未来。每架 drone 覆盖一个不同模式 → 无论目标选择哪条路径，都有一架 drone 在拦截位置。

**数学定义**：

```
给定:
  GMM 模式质心: mode_center_k = mean_{h=1..T_pred}(gmm_means_{k,h})    k=1,2,3
  drone 位置: p_{i,mid}   (取计划轨迹中间点)

构建距离矩阵 D ∈ R^{3×3}:
  D_{i,k} = || p_{i,mid} - mode_center_k ||

使用匈牙利算法求解最优一对一匹配:
  assignment = Hungarian(D)   # 最小化总距离

R_mode_cover = exp(-mean_{(i,k) in assignment} D_{i,k} / σ_mode)
```

**为什么这样设计**：
- 匈牙利匹配确保每架 drone 被分配不同模式 → 显式避免扎堆
- 使用中间航路点而非轨迹终点 → drone 正在前往该模式的方向
- 配合 R_encircle，同时保证角度分散 AND 覆盖不同模式

**与 R_encircle 的关系**：
- R_encircle：纯几何角度分散（不管 GMM 模式在哪）
- R_mode_cover：语义级分散（每机盯一个预测模式）
- 两者互补：目标可能有两种模式在相近方向 → R_encircle 低但 R_mode_cover 可区分

---

### 2.4 R_block — 球门拦截奖励

**含义**：奖励 drone 位于**目标预测位置**与**球门**之间的连线上。

**为什么越高越好**：目标最终要逃向球门，拦截球门方向是最有效的围堵策略。

**数学定义**：

```
给定:
  目标预测位置: target_pred_pos  (取 GMM 最高权重模式的最后时刻)
  球门区域中心: goal_center = [4.0, 0.0, 2.5]
  
对每个 drone i:
  v_target_to_goal = goal_center - target_pred_pos           # 目标→球门方向
  v_target_to_drone = p_{i,mid} - target_pred_pos            # 目标→drone 方向
  
  d_tg = ||v_target_to_goal||
  v_tg_norm = v_target_to_goal / (d_tg + 1e-8)
  
  # 投影 (越多越好: drone 在连线方向上)
  proj_i = dot(v_target_to_drone, v_tg_norm)
  
  # 垂直偏差 (越少越好: drone 偏离连线越少)
  perp_i = ||v_target_to_drone - proj_i * v_tg_norm||
  
  # 综合得分
  block_score_i = sigmoid(proj_i / σ_proj) * exp(-perp_i / σ_perp)
  
R_block = mean_i(block_score_i)
```

**σ_proj** ≈ 1.0m, **σ_perp** ≈ 1.0m

**为什么这样设计**：
- `proj_i > 0`：drone 在目标和球门之间（正向拦截）
- `proj_i < 0`：drone 在目标后方（追尾，不拦截）
- `perp_i` 小：drone 正好在连线上
- sigmoid 而非线性：drone 不需要在连线上 10 米远，在 1-2 米内即足够

---

### 2.5 R_smooth — 轨迹平滑奖励

**含义**：惩罚轨迹的高加速度和高 jerk，与 minimum snap 目标一致。

**为什么越高越好**：平滑轨迹 → 底层控制器更容易跟踪 → 更节能 → sim-to-real 差距小。

**数学定义**：

```
给定 drone 轨迹: [p_{i,1}, ..., p_{i,H}], dt = 0.05s

速度: v_{i,h} = (p_{i,h} - p_{i,h-1}) / dt          h=1..H
加速度: a_{i,h} = (v_{i,h} - v_{i,h-1}) / dt        h=1..H-1  
jerk:   j_{i,h} = (a_{i,h} - a_{i,h-1}) / dt        h=1..H-2

R_smooth = -w_acc * mean_h(||a_{i,h}||²) - w_jerk * mean_h(||j_{i,h}||²)
```

**w_acc** = 0.01, **w_jerk** = 0.005

**为什么这样设计**：
- 二次惩罚比线性更强调抑制 outlier
- jerk 权重为 acc 的一半（jerk 更敏感但控制精度要求低）
- 这个奖励与 minimum snap 轨迹生成器的优化目标一致 → 生成器和 Actor 目标对齐

---

### 2.6 R_sep — 安全分离奖励

**含义**：惩罚 drone 之间的碰撞风险。

**为什么越高越好**：安全 → 不会撞机 → 可以更激进地接近目标。

**数学定义**：

```
对每对 drone (i, j), i ≠ j:
  d_ij = ||p_{i,mid} - p_{j,mid}||
  
  separation_violation = max(0, d_min - d_ij)

R_sep = -mean_{i≠j}(separation_violation)
```

**d_min** = 0.5m（Crazyflie 安全距离）

**为什么这样设计**：
- 只在过近时惩罚，d > d_min 时不奖励（避免 drone 过度远离）
- 与 R_encircle 配合：R_encircle 从上方约束角度分布，R_sep 从下方提供最小距离
- 软约束而非硬约束：RL 可以在必要时牺牲间距换取拦截

---

### 2.7 R_early — 尽早拦截奖励

**含义**：奖励在目标远离球门时就完成拦截，而非等到目标逼近球门才行动。

**为什么越高越好**：早拦截 → 容错空间大 → 真机通信延迟下也能成功。

**数学定义**：

```
给定:
  目标到球门的距离: d_goal_target = ||target_pos - goal_center||
  
对每个 drone i:
  d_intercept,i = min_h ||p_{i,h} - target_pred_h||    # 轨迹上的最近距离

R_early,i = sigmoid(d_goal_target / σ_goal) * (1 - d_intercept,i / d_max)

R_early = mean_i(R_early,i)
```

**σ_goal** = 1.0m, **d_max** = 12.0m (arena 对角线)

**为什么这样设计**：
- `sigmoid(d_goal_target / 1.0)`：目标离球门 > 2m 时接近 1（鼓励远距离拦截），< 2m 时迅速衰减（太晚了，拦截意义不大）
- `(1 - d_intercept / 12)`：drone 越接近目标预测位置奖励越高
- 综合效果：鼓励在目标离球门还远时就贴近目标，不要拖到最后一刻

---

### 2.8 R_terminal — 终端事件奖励

**保持现有设计**：

| 事件 | 奖励 | 说明 |
|---|---|---|
| 捕获目标 | **+50** | episode 成功 |
| 目标到达球门 | **-40** | episode 失败 |
| episode 超时 | **-8** | 不够好但比球门好 |
| drone 碰撞 | **-40** | 严重惩罚（撞地/撞墙/互撞） |
| drone 落地 | **-40** | 无人机失去机动能力 |

## 3. 总奖励与权重

```
R_total =  w1 * R_intercept     推荐 2.0
         + w2 * R_encircle      推荐 1.5
         + w3 * R_mode_cover    推荐 1.0
         + w4 * R_block         推荐 1.0
         + w5 * R_smooth        推荐 0.5
         + w6 * R_sep           推荐 0.5
         + w7 * R_early         推荐 1.0
         + w8 * R_terminal      (50, -40, -8, -40, -40)
```

**权重设计原则**：

| 原则 | 说明 |
|---|---|
| R_intercept 权重最高 (2.0) | 这是核心目标：接近目标的未来位置 |
| R_encircle + R_mode_cover 次高 (1.5+1.0) | 防止扎堆 + 语义覆盖，协同能力的核心 |
| R_block + R_early 中等 (1.0+1.0) | 策略偏好：挡球门 + 早行动 |
| R_smooth + R_sep 偏低 (0.5+0.5) | 辅助约束，不能压倒核心目标 |
| 所有密集奖励量级 ≈ 0~3 | 与终端奖励 50 保持 20:1 的比例，确保稀疏奖励主导最终目标 |

**验证**：假设完美场景（围捕成功），密集奖励总和约：
```
2.0*1.0 + 1.5*0.67 + 1.0*1.0 + 1.0*1.0 + 0.5*0 + 0.5*0 + 1.0*1.0 = 2.0+1.0+1.0+1.0+1.0 = 6.0
```
每步最多 6.0，200 步 episode 约 1200 密集奖励 vs 终端 50 → 密集:终端 ≈ 24:1。可能需要调低密集权重或增大终端奖励，以免密集奖励主导策略。

**建议调整**：将所有密集权重 ÷ 2，使密集:终端 ≈ 12:1，更合理。

```
调整后:
  R_total =  1.0 * R_intercept
           + 0.75 * R_encircle
           + 0.5 * R_mode_cover
           + 0.5 * R_block
           + 0.25 * R_smooth
           + 0.25 * R_sep
           + 0.5 * R_early
           + R_terminal
```

## 4. 奖励实现伪代码

```python
def compute_rewards(drone_traj, target_pred, target_pos, target_vel, goal_center, cfg):
    """
    drone_traj:  [E, N, H, 3]   Actor 输出的航路点 (世界坐标)
    target_pred: {
        gmm_means:  [E, K, T, 3]   GMM 预测的未来位置
        gmm_weights: [E, K]        模式权重
    }
    target_pos:  [E, 1, 3]   目标当前位置
    target_vel:  [E, 1, 3]   目标当前速度
    goal_center: [3]          球门中心
    """

    E, N, H, _ = drone_traj.shape
    K = target_pred["gmm_means"].shape[1]

    # 1. 前瞻拦截奖励
    d_min = compute_min_spatial_distance(
        drone_traj,                        # [E,N,H,3]
        target_pred["gmm_means"],          # [E,K,T,3]
    )  # → [E, N]
    r_intercept = torch.exp(-d_min / cfg.sigma_intercept)  # [E,N]

    # 2. 角度包围奖励
    target_center = (target_pred["gmm_means"] * target_pred["gmm_weights"][..., None, None]).sum(2).mean(2)
    # → [E, 3] 加权质心
    mid_idx = H // 2
    drone_mid = drone_traj[:, :, mid_idx]  # [E,N,3]
    theta = torch.atan2(
        drone_mid[..., 1] - target_center[..., 1:2],
        drone_mid[..., 0] - target_center[..., 0:1],
    )  # [E,N]
    r_encircle = compute_angular_coverage_reward(theta)  # [E]
    close_mask = (d_min.min(dim=1).values < cfg.encircle_range).float()  # [E]
    r_encircle = r_encircle * close_mask

    # 3. 模式覆盖奖励
    mode_centers = target_pred["gmm_means"].mean(dim=2)  # [E,K,3]
    dist_matrix = torch.cdist(drone_mid, mode_centers)   # [E,N,K]
    # 匈牙利匹配 (per env, per agent)
    assignment = batched_hungarian(dist_matrix)
    r_mode_cover = torch.exp(-dist_matrix.gather(2, assignment).mean(dim=1) / cfg.sigma_mode)

    # 4. 球门拦截
    target_pred_final = target_pred["gmm_means"][:, 0, -1]  # 最高权重模式的最后时刻
    v_tg = goal_center - target_pred_final
    v_td = drone_mid - target_pred_final.unsqueeze(1)
    proj = (v_td * v_tg.unsqueeze(1)).sum(-1) / (v_tg.norm(dim=-1, keepdim=True) + 1e-8)
    perp = (v_td - proj.unsqueeze(-1) * v_tg.unsqueeze(1)).norm(dim=-1)
    r_block = (torch.sigmoid(proj / cfg.sigma_proj) * torch.exp(-perp / cfg.sigma_perp)).mean(dim=1)

    # 5. 轨迹平滑
    v = (drone_traj[:, :, 1:] - drone_traj[:, :, :-1]) / cfg.dt    # [E,N,H-1,3]
    a = (v[:, :, 1:] - v[:, :, :-1]) / cfg.dt                       # [E,N,H-2,3]
    j = (a[:, :, 1:] - a[:, :, :-1]) / cfg.dt                       # [E,N,H-3,3]
    r_smooth = -cfg.w_acc * (a.norm(dim=-1)**2).mean() - cfg.w_jerk * (j.norm(dim=-1)**2).mean()

    # 6. 安全分离
    d_drone = torch.cdist(drone_mid, drone_mid)  # [E,N,N]
    sep_violation = torch.relu(cfg.d_min - d_drone)
    r_sep = -sep_violation.sum(dim=(1,2)) / (N * (N-1))

    # 7. 尽早拦截
    d_goal_target = (target_pos.squeeze(1) - goal_center).norm(dim=-1)  # [E]
    r_early = torch.sigmoid(d_goal_target / cfg.sigma_goal) * (1 - d_min.mean(dim=1) / cfg.d_max)

    # 8. 终端奖励 (保持现有)
    # ...

    rewards = (
        cfg.w_intercept * r_intercept
        + cfg.w_encircle * r_encircle.unsqueeze(-1).expand(-1, N)
        + cfg.w_mode_cover * r_mode_cover.unsqueeze(-1).expand(-1, N)
        + cfg.w_block * r_block.unsqueeze(-1).expand(-1, N)
        + cfg.w_smooth * r_smooth
        + cfg.w_sep * r_sep.unsqueeze(-1).expand(-1, N)
        + cfg.w_early * r_early.unsqueeze(-1).expand(-1, N)
        + terminal_rewards
    )
    return rewards  # [E, N]

def compute_min_spatial_distance(drone_traj, gmm_means):
    """计算 drone 轨迹与 GMM 预测轨迹之间的最小空间距离。
    
    drone_traj: [E, N, H, 3]
    gmm_means:  [E, K, T, 3]
    Returns:    [E, N]  每个 drone 到最近 GMM mode 最近时步的距离
    """
    E, N, H, _ = drone_traj.shape
    K = gmm_means.shape[1]
    T = gmm_means.shape[2]

    # 展平: [E, N*H, 3] vs [E, K*T, 3]
    drones_flat = drone_traj.reshape(E, N * H, 3)
    gmm_flat = gmm_means.reshape(E, K * T, 3)

    # pairwise distance: [E, N*H, K*T]
    dist = torch.cdist(drones_flat, gmm_flat)

    # reshape → [E, N, H, K, T] → min over (H, K, T) → [E, N]
    dist = dist.reshape(E, N, H, K, T)
    return dist.amin(dim=(2, 3, 4))


def compute_angular_coverage_reward(theta):
    """计算 N 个 drone 的角度覆盖奖励。
    
    theta: [E, N]  角度 in radians
    Returns: [E]
    """
    theta_sorted, _ = theta.sort(dim=1)  # [E,N]
    # 循环间隙
    gaps = theta_sorted[:, 1:] - theta_sorted[:, :-1]               # [E,N-1]
    wrap_gap = 2 * torch.pi - (theta_sorted[:, -1] - theta_sorted[:, 0])  # [E]
    all_gaps = torch.cat([gaps, wrap_gap.unsqueeze(-1)], dim=1)     # [E,N]
    g_max = all_gaps.max(dim=1).values                               # [E]
    return 1.0 - g_max / (2 * torch.pi)
```

## 5. 训练阶段化策略 (Curriculum)

不同训练阶段侧重点不同，防止初期稀疏奖励 + 复杂密集奖励导致不收敛：

| 阶段 | 步数 | 策略 |
|---|---|---|
| **Phase 1: 基础追踪** (0-20%) | ~2M steps | 只用 R_terminal + R_intercept + R_sep。学会基本前飞和接近目标 |
| **Phase 2: 协同引入** (20-50%) | ~3M steps | 逐步加入 R_encircle + R_mode_cover。权重从 0 → 目标值的 50% |
| **Phase 3: 策略优化** (50-80%) | ~3M steps | 所有权重到目标值。加入 R_block + R_early |
| **Phase 4: 精细调优** (80-100%) | ~2M steps | 全权重。可能需要微调 R_smooth 权重 |

权重调度：

```python
phase = training_progress  # 0..1

# R_encircle 和 R_mode_cover 在第 20% 之后逐步激活
coop_ramp = ((phase - 0.2) / 0.3).clamp(0.0, 1.0)  # 0.2→0.5 线性增长

w_encircle  = 0.75 * coop_ramp
w_mode_cover = 0.5 * coop_ramp
w_block     = 0.5 * ((phase - 0.5) / 0.3).clamp(0.0, 1.0)
w_early     = 0.5 * ((phase - 0.5) / 0.3).clamp(0.0, 1.0)
```

## 6. 若奖励设计正确但训练效果不佳 → 最小测试方案

### 6.1 诊断框架

按优先级排查：

```text
诊断 1: 检查各项奖励的时间序列
  ├─ 绘制每项奖励的 episode 均值曲线
  ├─ R_intercept 是否单调上升？如果不是 → Actor 没学会接近预测位置
  ├─ R_encircle 是否上升？如果不是 → Actor 没学会角度分散
  └─ 终端奖励（捕获率）是否上升？

诊断 2: 检查奖励间的冲突
  ├─ R_intercept ↑ 但 R_encircle ↓ → 可能三机全挤到最近的预测点
  ├─ R_encircle ↑ 但 R_intercept ↓ → 分散过度，离目标太远
  └─ R_smooth 很大负值 → 轨迹抖动，Actor 输出不稳定

诊断 3: 检查 GMM 预测质量
  ├─ GMM 预测是否准确？(在 hideandseek 中记录 prediction error)
  ├─ 如果 GMM 预测偏差 >1m → Actor 基于错误预测学习 → 垃圾进垃圾出
  └─ 替代方案：使用运动学外推 (匀速/匀加速) 替代 GMM 做 ablation
```

### 6.2 Ablation 测试矩阵

每次只改一个变量，对比捕获率：

| Test | 改动 | 预期 |
|---|---|---|
| **Baseline** | 仅 R_terminal | 基础追尾，捕获率作为下界 |
| **+Intercept** | Baseline + R_intercept | 捕获率应提升 >20% |
| **+Encircle** | +Intercept + R_encircle | 视觉上应看到三角围捕 |
| **+ModeCover** | +Encircle + R_mode_cover | 三机趋向不同 GMM 模式 |
| **+Block** | +ModeCover + R_block | 拦截方向偏向球门 |
| **+Early** | +Block + R_early | 更早完成拦截 |
| **Full** | 全部奖励 | 应达到最高捕获率 |

### 6.3 最小可视化验证

训练过程中用 `eval_videos/` 录制以下场景的 rollout：

| 场景 | 验证内容 |
|---|---|
| 目标直冲球门 | drone 是否在球门前方拦截（而非追尾）？ |
| 目标横向规避 | 三机是否分散在不同方向堵截？ |
| 目标静止 | 三机是否形成三角包围而非挤在一起？ |
| 目标高速转弯 | 轨迹是否平滑无突变？ |

### 6.4 快速调参策略

| 症状 | 调整 |
|---|---|
| 三机扎堆 | ↑ w_encircle, ↑ w_mode_cover, ↓ w_intercept |
| 太分散，围不住 | ↓ w_encircle, ↑ w_intercept |
| 追尾（无前瞻） | ↑ w_early, 检查 GMM 预测是否在观测中 |
| 轨迹抖动 | ↑ w_smooth, 检查 Actor log_std 是否过大 |
| 不收敛 | 回到 Phase 1 baseline，确认基础追踪可行后再加协同 |
| 某项奖励一直为 0 | 检查计算是否有 bug（维度、NaN、范围） |

### 6.5 最简单的"冒烟测试"

在完整训练前，用一个 **单步监督信号** 验证所有奖励计算正确：

```python
def smoke_test_rewards():
    """验证所有奖励函数输出合理且可微。"""
    B, N, H = 2, 3, 10
    drone_traj = torch.randn(B, N, H, 3, requires_grad=True)
    gmm_means = torch.randn(B, 3, 5, 3)
    gmm_weights = torch.ones(B, 3) / 3

    rewards = compute_rewards(drone_traj, {
        "gmm_means": gmm_means,
        "gmm_weights": gmm_weights,
    }, target_pos=..., target_vel=..., goal_center=...)

    # 1. 无 NaN
    assert not torch.isnan(rewards).any()

    # 2. 梯度非零
    loss = rewards.sum()
    loss.backward()
    assert drone_traj.grad is not None
    assert drone_traj.grad.abs().sum() > 0

    # 3. 范围检查
    assert (r_intercept >= 0).all() and (r_intercept <= 1).all()
    assert (r_encircle >= 0).all() and (r_encircle <= 0.667 + 1e-5).all()

    # 4. 排列等变性
    # 交换 drone 0/1 的轨迹 → 奖励应相应交换
```

## 7. 总结

| 设计要素 | 解决什么问题 | 数学形式 |
|---|---|---|
| **R_intercept** | 追尾滞后 → 前瞻拦截 | $\exp(-d_{\min}/\sigma)$ |
| **R_encircle** | 扎堆 → 角度分散 | $1 - g_{\max}/2\pi$ |
| **R_mode_cover** | 单模式拥挤 → 多模式覆盖 | 匈牙利匹配 + $\exp(-\bar{d}/\sigma)$ |
| **R_block** | 无策略偏好 → 挡球门 | $\sigma(\text{proj}) \cdot \exp(-\text{perp}/\sigma)$ |
| **R_smooth** | 轨迹抖动 → 平滑 | $-\|\mathbf{a}\|^2 - \|\mathbf{j}\|^2$ |
| **R_sep** | 碰撞风险 → 安全距离 | $-\max(0, d_{\min} - d)$ |
| **R_early** | 拖延 → 尽早行动 | $\sigma(d_{\text{goal}}) \cdot (1 - d/d_{\max})$ |

**核心设计原则**：所有空间奖励基于**目标预测未来位置**，所有协同奖励基于**角度分散 + 模式分配**。
