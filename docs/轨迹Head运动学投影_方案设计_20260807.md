## 0. 总体链路

```text
cooperative_future_tokens  [B, N, H=10, D=128]
        │
        ▼
┌─ PositionHead ───────────────────────────────┐
│  token → MLP → tanh → pos_scale → pos_delta  │  [B, N, H, 3]  (相对当前位置)
└──────────────────────────────────────────────┘
        │
        ▼
┌─ VelocityHead ───────────────────────────────┐
│  token → MLP → tanh → vel_scale → vel_raw    │  [B, N, H, 3]
└──────────────────────────────────────────────┘
        │
        ▼
┌─ KinematicProjection ────────────────────────┐
│  ① 速度约束：clip ||v|| ≤ v_max              │
│  ② 加速度约束：clip ||a|| ≤ a_max            │
│  ③ 倾角约束：||a_xy|| ≤ (9.81+a_z)·tan(θ_max)│
│  ④ 边界约束：clamp pos ∈ arena               │
│  ⑤ 一致性：pos ↔ vel 有限差分一致性校正       │
└──────────────────────────────────────────────┘
        │
        ├── feasible_positions [B, N, H, 3]  (世界坐标)
        └── feasible_velocities [B, N, H, 3]
        │
        ▼
┌─ 取前 0.1s (h=0,1) ─────────────────────────┐
│  ref_waypoint = feasible_positions[:,:,1]     │
│  ref_velocity  = feasible_velocities[:,:,1]   │
│  desired_acc = (ref_velocity - cur_vel) / dt  │
└──────────────────────────────────────────────┘
        │
        ▼
┌─ 现有控制器 _acceleration_to_pidrate_action ─┐
│  acc → tilt约束 → SO3期望姿态 → PIDRate     │
│  → thrust + body_rates → drone.apply_action   │
└──────────────────────────────────────────────┘
```

$$
\begin{aligned}
\| \mathbf{v}_h \| &\le v_{\max} \\[4pt]
\| \mathbf{a}_h \| &\le a_{\max} \\[4pt]

r_{\text{arena}} &\ge \sqrt{x_h^2 + y_h^2} \\[4pt]

\end{aligned}

## 2. PositionHead

### 2.1 设计思路

每个 Future Token 输出一个**相对于当前自身位置**的位移向量。由于网络不知道世界坐标系绝对范围，用 tanh 将输出压缩到有限区间，再用可学习 scale 放缩到物理范围。

### 2.2 结构

```python
class PositionHead(nn.Module):
    """
    Input:  future_tokens [B, N, H, D]
    Output: pos_delta     [B, N, H, 3]  相对当前位置的位移 (有约束)
            pos_raw       [B, N, H, 3]  tanh 前的原始值 (供 PPO log_prob)
    """

    def __init__(self, cfg: TrajectoryHeadConfig):
        super().__init__()
        dm = cfg.d_model
        self.net = nn.Sequential(
            nn.Linear(dm, dm),
            nn.SiLU(),
            nn.Linear(dm, dm // 2),
            nn.SiLU(),
            nn.Linear(dm // 2, 3),
        )
        # 可学习 scale：初始 ≈ 0.15m/步 → 3.0m/s 最大速度下约 10 步走 1.5m+ 的探索范围
        self.pos_scale = nn.Parameter(torch.tensor(0.15))

    def forward(self, future_tokens: Tensor) -> tuple[Tensor, Tensor]:
        raw = self.net(future_tokens)                     # [B,N,H,3]
        pos_delta = torch.tanh(raw) * self.pos_scale      # [B,N,H,3]
        return pos_delta, raw
```

**关键选择说明**：

- `pos_scale=0.15` 意味着单步最大位移 0.15m，对应瞬时速度 3.0 m/s（0.15/0.05 = 3.0），恰好等于 $v_{\max}$
- 初始化为小值让网络从保守策略开始，逐步学会利用全部速度范围

### 2.3 tanh 与 PPO log_prob

使用 tanh 压缩后，PPO 动作分布需使用 **Squashed Gaussian**（即 `TanhNormal`），log_prob 中已包含 tanh 的 Jacobian 修正项：

$$\log \pi(a|s) = \log \mathcal{N}(u|\mu,\sigma) - \sum_i \log(1 - \tanh^2(u_i))$$

其中 $u$ 是 pre-tanh 的 raw 值，$a = \text{scale} \cdot \tanh(u)$ 是实际输出。

项目中已有 `TanhNormal` 实现（`omni_drones/learning/modules/distributions.py`），可直接复用。

## 3. VelocityHead

### 3.1 设计思路

每个 Future Token 同时输出期望速度。与 Position Head 独立输出，二者的不一致由 KinematicProjection 调和。

### 3.2 结构

```python
class VelocityHead(nn.Module):
    """
    Input:  future_tokens [B, N, H, D]
    Output: vel           [B, N, H, 3]  速度向量 (有约束)
            vel_raw       [B, N, H, 3]  tanh 前的原始值 (供 PPO log_prob)
    """

    def __init__(self, cfg: TrajectoryHeadConfig):
        super().__init__()
        dm = cfg.d_model
        self.net = nn.Sequential(
            nn.Linear(dm, dm),
            nn.SiLU(),
            nn.Linear(dm, dm // 2),
            nn.SiLU(),
            nn.Linear(dm // 2, 3),
        )
        self.vel_scale = nn.Parameter(torch.tensor(3.0))  # = v_max

    def forward(self, future_tokens: Tensor) -> tuple[Tensor, Tensor]:
        raw = self.net(future_tokens)                    # [B,N,H,3]
        vel = torch.tanh(raw) * self.vel_scale           # [B,N,H,3]
        return vel, raw
```

**注意**：Velocity Head 的 tanh 只保证分量不超过 ±3.0 m/s，**不保证合速度范数 ≤ 3.0**（例如同时 x=2.5, y=2.5 时，合速度 ≈ 3.54 > 3.0）。这个由 KinematicProjection 处理。

## 4. KinematicProjection（核心）

### 4.1 设计思路

输入是网络输出的 pos_delta 和 vel，需要输出物理可行的轨迹。关键问题：

- Position Head 和 Velocity Head 是两个独立路径，它们的输出可能不一致（例如 pos 暗示向右，vel 暗示向左）
- 所有约束需要在一步投影中满足

采用 **"信任 Position → 修复 Velocity → 约束加速度 → 反推 Position"** 的策略：

```text
pos_delta (网络) ──→ 绝对位置 p_net
                         │
                         ▼
           有限差分速度 v_fd = (p_h - p_{h-1}) / dt
                         │
                         ▼
           融合速度：v = α·v_net + (1-α)·v_fd   (α 可学习，初始偏向 FD)
                         │
                         ▼
           约束速度：‖v‖ ≤ v_max
                         │
                         ▼
           有限差分加速度 a_fd = (v_h - v_{h-1}) / dt
                         │
                         ▼
           约束加速度：‖a‖ ≤ a_max, ‖a_xy‖ ≤ (9.81+a_z)·tanθ_max
                         │
                         ▼
           从约束后的加速度重新积分 → feasible positions & velocities
                         │
                         ▼
           边界约束：clamp pos ∈ arena
```

### 4.2 代码结构

```python
@dataclass
class KinematicProjectionConfig:
    """运动学投影的超参数。"""
    dt: float = 0.05                 # 轨迹步长
    v_max: float = 3.0               # 最大速度 (m/s)
    a_max: float = 6.0               # 最大加速度 (m/s²)
    a_vertical_max: float = 5.5      # 垂直加速度上限
    max_tilt_deg: float = 35.0       # 最大倾角 (度)
    arena_radius: float = 6.0        # 场地半径
    z_min: float = 0.3               # 最小高度
    z_max: float = 5.0               # 最大高度
    velocity_blend_alpha: float = 0.3 # v = α·v_net + (1-α)·v_fd 中的 α


class KinematicProjection(nn.Module):
    """
    将网络输出的 pos_delta + vel 投影到物理可行轨迹。

    所有操作为可微（使用 where/relu/clamp 等分段函数，PPO 前向不需要梯度）。
    在 rollout 阶段可注入噪声模拟传感器误差；PPO update 阶段完全确定性。

    Input:
        pos_delta:   [B, N, H, 3]  相对当前位置的位移 (PositionHead 输出)
        vel_net:     [B, N, H, 3]  网络速度输出 (VelocityHead 输出)
        current_pos: [B, N, 3]     当前世界坐标
        current_vel: [B, N, 3]     当前世界速度

    Output:
        positions: [B, N, H, 3]    绝对世界坐标 (物理可行)
        velocities: [B, N, H, 3]   速度向量 (物理可行)
        accelerations: [B, N, H, 3] 加速度 (诊断用)
    """

    def __init__(self, cfg: KinematicProjectionConfig):
        super().__init__()
        self.cfg = cfg
        self.alpha = nn.Parameter(torch.tensor(cfg.velocity_blend_alpha))

    def forward(
        self,
        pos_delta: Tensor,
        vel_net: Tensor,
        current_pos: Tensor,
        current_vel: Tensor,
    ) -> dict[str, Tensor]:
        B, N, H, _ = pos_delta.shape
        dt = self.cfg.dt
        vmax = self.cfg.v_max
        amax = self.cfg.a_max
        az_max = self.cfg.a_vertical_max
        tilt_tan = math.tan(math.radians(self.cfg.max_tilt_deg))

        # ── Step 1: 网络绝对位置 ──────────────────────────────
        # cumsum along time: 绝对位置 = 当前位置 + 累积位移
        pos_net = current_pos.unsqueeze(2) + pos_delta.cumsum(dim=2)
        # [B, N, H, 3]

        # ── Step 2: 有限差分速度 (from positions) ─────────────
        v_fd_0 = (pos_net[:, :, 0] - current_pos) / dt         # [B,N,3]
        v_fd_h = (pos_net[:, :, 1:] - pos_net[:, :, :-1]) / dt # [B,N,H-1,3]
        v_fd = torch.cat([v_fd_0.unsqueeze(2), v_fd_h], dim=2)  # [B,N,H,3]

        # ── Step 3: 融合速度 ──────────────────────────────────
        alpha = torch.sigmoid(self.alpha)
        v_blend = alpha * vel_net + (1 - alpha) * v_fd          # [B,N,H,3]

        # ── Step 4: 速度范数约束 ──────────────────────────────
        v_norm = v_blend.norm(dim=-1, keepdim=True)
        v_scale = torch.where(
            v_norm > vmax,
            vmax / (v_norm + 1e-8),
            torch.ones_like(v_norm)
        )
        v = v_blend * v_scale                                   # [B,N,H,3]

        # ── Step 5: 有限差分加速度 ────────────────────────────
        a_fd_0 = (v[:, :, 0] - current_vel) / dt                # [B,N,3]
        a_fd_h = (v[:, :, 1:] - v[:, :, :-1]) / dt              # [B,N,H-1,3]
        a = torch.cat([a_fd_0.unsqueeze(2), a_fd_h], dim=2)    # [B,N,H,3]

        # ── Step 6: 加速度约束 ────────────────────────────────
        # 6a. 总加速度范数约束
        a_norm = a.norm(dim=-1, keepdim=True)
        a_scale = torch.where(
            a_norm > amax,
            amax / (a_norm + 1e-8),
            torch.ones_like(a_norm)
        )
        a = a * a_scale

        # 6b. 垂直加速度单独约束 (叠加上限)
        a_z = a[..., 2:3]
        a_z_scale = torch.where(
            a_z.abs() > az_max,
            az_max / (a_z.abs() + 1e-8),
            torch.ones_like(a_z)
        )
        a[..., 2:3] = a_z * a_z_scale

        # 6c. 倾角约束: ||a_xy|| ≤ (9.81 + a_z) · tan(θ_max)
        a_xy = a[..., :2]
        a_xy_norm = a_xy.norm(dim=-1, keepdim=True)
        a_xy_max = torch.clamp((9.81 + a[..., 2:3]) * tilt_tan, min=0.1)
        a_xy_scale = torch.where(
            a_xy_norm > a_xy_max,
            a_xy_max / (a_xy_norm + 1e-8),
            torch.ones_like(a_xy_norm)
        )
        a[..., :2] = a_xy * a_xy_scale

        # 注意：修改 a 的分量后可能破坏总范数约束，再执行一次
        a_norm2 = a.norm(dim=-1, keepdim=True)
        a_scale2 = torch.where(
            a_norm2 > amax,
            amax / (a_norm2 + 1e-8),
            torch.ones_like(a_norm2)
        )
        a = a * a_scale2

        # ── Step 7: 从约束加速度积分得可行轨迹 ──────────────
        v_feasible = [current_vel]
        p_feasible = [current_pos]

        for h in range(H):
            v_next = v_feasible[-1] + a[:, :, h] * dt
            p_next = p_feasible[-1] + v_next * dt
            v_feasible.append(v_next)
            p_feasible.append(p_next)

        v_feasible = torch.stack(v_feasible[1:], dim=2)   # [B,N,H,3]
        p_feasible = torch.stack(p_feasible[1:], dim=2)   # [B,N,H,3]

        # ── Step 8: 场地边界约束 ──────────────────────────────
        # xy: 圆形边界
        r_xy = p_feasible[..., :2].norm(dim=-1, keepdim=True)
        r_scale = torch.where(
            r_xy > self.cfg.arena_radius,
            self.cfg.arena_radius / (r_xy + 1e-8),
            torch.ones_like(r_xy)
        )
        p_feasible[..., :2] = p_feasible[..., :2] * r_scale

        # z: 高度边界
        p_feasible[..., 2] = p_feasible[..., 2].clamp(
            self.cfg.z_min, self.cfg.z_max
        )

        return {
            "positions": p_feasible,           # [B,N,H,3]  世界坐标 (物理可行)
            "velocities": v_feasible,          # [B,N,H,3]  速度向量 (物理可行)
            "accelerations": a,               # [B,N,H,3]  约束后加速度
            "pos_net_unconstrained": pos_net,  # [B,N,H,3]  约束前网络位置 (诊断)
            "vel_blend": v_blend,             # [B,N,H,3]  融合速度 (诊断)
            "alpha": alpha,                   # scalar     速度融合权重
        }
```

### 4.3 可微性说明

- `torch.where(condition, a, b)` — 前向分段、反向传梯度到激活分支（与 ReLU 类似），完全可微
- `torch.clamp` — 在约束边界处梯度为 0，这通常对 RL 是**有益的**（让网络学会不依赖被 clamp 的维度）
- 循环积分 `for h in range(H)` — 梯度通过多次加法累积，等价于展开的 RNN，PyTorch autograd 自动处理
- **前向使用投影**确保 rollout 动作物理可行；**PPO update 对 raw 值（pre-tanh）算 log_prob**，因为环境实际执行的是投影后动作

## 5. PPO 动作空间设计

### 5.1 "动作"是什么？

本方案中 PPO 的"动作"是**两个 Head 的 pre-tanh raw 值拼接**：

```python
# 动作 = [pos_raw flattened, vel_raw flattened]
# 每个分量独立 Normal 分布，经 tanh + scale 变换为 Squashed Gaussian

action_dim = N * H * 3 + N * H * 3  # 3×10×3 + 3×10×3 = 180
```

### 5.2 分布

使用项目中已有的 `TanhNormal`（即 `IndependentNormal` + `TanhTransform`）：

```python
from omni_drones.learning.modules.distributions import TanhNormal

loc = torch.cat([pos_raw.flatten(-3), vel_raw.flatten(-3)], dim=-1)   # [B, action_dim]
scale = self.log_std.exp().expand_as(loc)                              # 可学习或状态条件

dist = TanhNormal(loc, scale)
action_raw = dist.rsample()     # 采样 pre-tanh 值
action = torch.tanh(action_raw) * action_scale  # 变换到物理范围

log_prob = dist.log_prob(action_raw).sum(-1)    # 包含 tanh Jacobian 修正
```

### 5.3 scale 参数

需要把 pre-tanh raw value 映射到物理范围：

```python
action_scale = torch.cat([
    torch.full((N*H*3,), pos_scale.item()),   # pos: 0.15
    torch.full((N*H*3,), vel_scale.item()),   # vel: 3.0
], dim=-1).to(device)
```

### 5.4 为什么在 pre-tanh 算 log_prob

PPO 更新需要正确评估采样动作在当前策略下的概率。如果对投影后动作算概率，投影的非线性（clamp、范数归一化）会使概率密度不可解。因此：

- **策略网络输出**：pre-tanh raw → tanh → scale → pos_delta / vel
- **环境执行**：pos_delta / vel → KinematicProjection → 实际轨迹
- **log_prob 计算**：对 pre-tanh raw 使用 TanhNormal.log_prob（投影视为环境转移的非平稳部分）

这符合 `TanhNormal` 的标准用法：actor 输出 mean/log_std → 采样 → tanh → scale → 送入环境。

## 6. 控制器接口

### 6.1 从轨迹到加速度命令

```python
def trajectory_to_accel_cmd(
    feasible_positions: Tensor,    # [B, N, H, 3]
    feasible_velocities: Tensor,   # [B, N, H, 3]
    current_pos: Tensor,           # [B, N, 3]
    current_vel: Tensor,           # [B, N, 3]
    execute_steps: int = 2,        # 执行前 N 步 (0.1s)
    dt: float = 0.05,
) -> Tensor:
    """
    从可行轨迹提取控制器加速度命令。

    策略: 用"前瞻一步"的位置和速度计算期望加速度:
        desired_acc = kp*(p_target - p_cur)/dt + kv*(v_target - v_cur)
                     ≈ (v_target - v_cur) / dt   (kp=0, kv=1 的特例)

    实际使用: 取第一步的参考状态来导出加速度。
    """
    # 取第一个轨迹点作为参考
    p_ref = feasible_positions[:, :, 0]      # [B,N,3]
    v_ref = feasible_velocities[:, :, 0]     # [B,N,3]

    # PD 风格: 位置偏差 + 速度偏差 → 期望加速度
    kp = 4.0   # 位置增益
    kv = 2.0   # 速度增益 (与现有 ot_config 一致)

    desired_acc = (
        kp * (p_ref - current_pos) / dt
        + kv * (v_ref - current_vel)
    )

    return desired_acc  # [B,N,3]
```

### 6.3 上一周期轨迹维护

每个 RL step 后，剩余轨迹需要作为下一周期的 `prev_plan`：

```python
def update_prev_plan(
    feasible_positions: Tensor,   # [B,N,H,3]  当前周期的可行轨迹 (世界坐标)
    feasible_velocities: Tensor,  # [B,N,H,3]
    current_pos: Tensor,          # [B,N,3]     新一帧的真实位置
    current_vel: Tensor,          # [B,N,3]
    execute_steps: int = 2,       # 已执行 2 步
    H: int = 10,
) -> tuple[Tensor, Tensor]:
    """
    删除已执行的前 execute_steps 个轨迹点，
    剩余轨迹相对于当前真实位置重新表达，
    补齐至长度 H。
    """
    # 1. 删除已执行的点
    remaining_pos = feasible_positions[:, :, execute_steps:]   # [B,N,H-execute_steps,3]
    remaining_vel = feasible_velocities[:, :, execute_steps:]

    # 2. 相对化: 减去当前真实位置
    rel_pos = remaining_pos - current_pos.unsqueeze(2)

    # 3. 补齐: 取最后一点保持 (匀速外推)
    if remaining_pos.shape[2] < H:
        pad_len = H - remaining_pos.shape[2]
        # 最后一点的速度用于外推
        last_vel = remaining_vel[:, :, -1:]                    # [B,N,1,3]
        # 补齐位置 = 最后位置 + 匀速外推
        extrap_steps = torch.arange(1, pad_len + 1, device=remaining_pos.device).float()
        extrap_steps = extrap_steps.view(1, 1, -1, 1) * 0.05  # [1,1,pad,1]
        extrap_pos = remaining_pos[:, :, -1:] + last_vel * extrap_steps
        extrap_rel_pos = extrap_pos - current_pos.unsqueeze(2)

        rel_pos = torch.cat([rel_pos, extrap_rel_pos], dim=2)
        # 补齐速度: 匀速
        rel_vel = torch.cat([remaining_vel, last_vel.expand(-1, -1, pad_len, -1)], dim=2)
        # 相对化
        rel_vel = rel_vel - current_vel.unsqueeze(2)
    else:
        rel_vel = remaining_vel - current_vel.unsqueeze(2)

    # 4. 构造 prev_plan: [B,N,H,6]  = [rel_pos(3), rel_vel(3)]
    prev_plan = torch.cat([rel_pos, rel_vel], dim=-1)

    # 5. 有效掩码: 真实轨迹点 = 1, 补齐点 = 0
    valid_len = remaining_pos.shape[2] - pad_len if 'pad_len' in dir() else remaining_pos.shape[2]
    prev_mask = torch.zeros(B, N, H, device=current_pos.device)
    prev_mask[:, :, :valid_len] = 1.0

    return prev_plan, prev_mask
```

## 7. 整合到 PPO 策略

### 7.1 完整 forward

```python
class TrajectoryPPOPolicy(nn.Module):
    """
    整合 CooperativeFutureTokenEncoder + PositionHead + VelocityHead
    + KinematicProjection 的完整轨迹策略。
    """

    def __init__(self, ...):
        self.future_encoder = CooperativeFutureTokenEncoder(cfg)
        self.pos_head = PositionHead(cfg)
        self.vel_head = VelocityHead(cfg)
        self.projection = KinematicProjection(cfg)

        # PPO 分布参数
        self.log_std = nn.Parameter(torch.zeros(N * H * 3 * 2) * 0.0)

    def forward(self, obs: TensorDict) -> tuple[TensorDict, Tensor]:
        """
        Returns:
            actions:   执行用动作 (thrust+body_rates 或 desired_acc)
            log_probs: PPO log_prob
        """
        # 1. 历史编码 → future tokens
        future_out = self.future_encoder(
            agent_history=obs["history"],
            current_pos=obs["relative_pos"],
            current_vel=obs["relative_vel"],
            prev_plan=obs["prev_plan"],
            prev_plan_mask=obs["prev_plan_mask"],
            gmm_mode_tokens=obs["gmm_mode_tokens"],
            gmm_point_tokens=obs["gmm_point_tokens"],
            gmm_weights=obs["gmm_weights"],
        )
        tokens = future_out["cooperative_future_tokens"]

        # 2. Position & Velocity Heads → raw values
        pos_delta, pos_raw = self.pos_head(tokens)
        vel, vel_raw = self.vel_head(tokens)

        # 3. 构造动作分布 (TanhNormal)
        action_raw = torch.cat([
            pos_raw.flatten(start_dim=1),   # [B, N*H*3]
            vel_raw.flatten(start_dim=1),   # [B, N*H*3]
        ], dim=-1)                           # [B, 2*N*H*3]

        dist = TanhNormal(action_raw, self.log_std.exp())
        sampled_raw = dist.rsample()

        # 4. 反展平 → pre-tanh raw → tanh → scale → 物理值
        pos_raw_sampled = sampled_raw[..., :N*H*3].view(B, N, H, 3)
        vel_raw_sampled = sampled_raw[..., N*H*3:].view(B, N, H, 3)
        pos_delta_sampled = torch.tanh(pos_raw_sampled) * self.pos_head.pos_scale
        vel_sampled = torch.tanh(vel_raw_sampled) * self.vel_head.vel_scale

        # 5. 运动学投影
        proj_out = self.projection(
            pos_delta_sampled, vel_sampled,
            obs["current_pos"], obs["current_vel"],
        )
        feasible_positions = proj_out["positions"]
        feasible_velocities = proj_out["velocities"]

        # 6. 转换为控制器命令
        desired_acc = trajectory_to_accel_cmd(
            feasible_positions, feasible_velocities,
            obs["current_pos"], obs["current_vel"],
        )

        # 7. log_prob (对 pre-tanh raw 值)
        log_prob = dist.log_prob(sampled_raw).sum(-1)

        return {
            "desired_acc": desired_acc,
            "feasible_positions": feasible_positions,
            "feasible_velocities": feasible_velocities,
            "pos_delta_raw": pos_raw_sampled,
            "vel_raw": vel_raw_sampled,
            **future_out,   # 包含诊断用的 attention 等
        }, log_prob
```

## 8. 备选方案：纯加速度 Head

如果觉得 Position+Velocity 双 Head 过于复杂，可以考虑更简单的替代方案：

### 8.1 方案 B：Acceleration Head

```python
class AccelerationHead(nn.Module):
    """直接输出各时间步的加速度命令。"""
    def __init__(self, cfg):
        self.net = nn.Sequential(
            nn.Linear(d_model, d_model), nn.SiLU(),
            nn.Linear(d_model, 3),
        )
        self.acc_scale = nn.Parameter(torch.tensor(3.0))  # 初始 ~3m/s²

    def forward(self, tokens):
        raw = self.net(tokens)
        acc = torch.tanh(raw) * self.acc_scale  # [B,N,H,3]
        return acc, raw
```

然后不需要 Velocity Head 和复杂的投影融合——从加速度直接积分得速度和位置，约束在积分过程中施加：

```python
def integrate_with_constraints(acc_raw, cur_pos, cur_vel, cfg):
    """从加速度+约束积分轨迹（替代 KinematicProjection）。"""
    v = [cur_vel]
    p = [cur_pos]
    for h in range(H):
        a = acc_raw[:, :, h]
        # 倾角约束
        a_xy = a[..., :2]
        a_xy_max = (9.81 + a[..., 2:3]) * tan_tilt
        a[..., :2] = a_xy * (a_xy_max / a_xy.norm(...).clamp_min(1e-6)).clamp(max=1)
        # 速度积分 & 约束
        v_next = v[-1] + a * dt
        v_next = clip_vector_norm(v_next, v_max)
        # 位置积分 & 边界
        p_next = p[-1] + v_next * dt
        p_next = clamp_to_arena(p_next)
        v.append(v_next)
        p.append(p_next)
    return torch.stack(p[1:]), torch.stack(v[1:])
```

### 8.2 方案 B 的速度来源：积分产生，非当前速度

**方案 B 虽然只输出加速度，但约束积分过程自动产生了速度序列。控制时用的是轨迹规划的参考速度，不是无人机当前速度。**

```text
Acc Head → a_raw [B,N,H,3]
              │
              ▼ integrate_with_constraints()
              │
              ├── v_feasible [B,N,H,3]  ← 每个时刻的轨迹规划速度
              └── p_feasible [B,N,H,3]  ← 每个时刻的轨迹规划位置
              │
              ▼ 取第一步 (h=0)
              │
        p_ref = p_feasible[:,:,0]    参考路径点
        v_ref = v_feasible[:,:,0]    参考速度 ← 来自轨迹, 非 cur_vel!

        desired_acc = kp·(p_ref - cur_pos)/dt + kv·(v_ref - cur_vel)
                              ↑ 位置追踪               ↑ 速度前馈
```

**为什么用轨迹速度而非当前速度？**
- 如果只用位置误差（`desired_acc = kp*(p_ref - cur_pos)/dt`），无人机在到达路径点时速度会趋近于 0，然后再加速去下一个点 → 轨迹不平滑
- 加上速度前馈（`kv*(v_ref - cur_vel)`），无人机会主动匹配轨迹规划的速度，实现平滑追踪

**与现有代码的对应关系**：项目中 `_target_velocity_to_pidrate_action` 已有这个模式：
```python
# hideandseek.py L1762-1765 (现有代码)
vel_error = desired_vel - current_vel
acc_cmd = self.target_uav_velocity_gain * vel_error + feedforward_acc
```

方案 B 的 `desired_acc` 就是这个 `acc_cmd`，直接送入 `_acceleration_to_pidrate_action`。

**优点**：
- 只需一个 Head，动作维减半（90 维）
- 加速度天然满足倾角约束
- 速度由积分自然产生，pos↔vel 天然一致
- 无需速度融合 α 参数

**缺点**：
- 速度是加速度的累积效果，无法直接表达"快速到某点然后停住"这类意图
- 位置和速度的"语义分离"不如双 Head 清晰

## 9. 方案对比

| 维度 | 方案 A: Pos+Vel 双 Head | 方案 B: Acc 单 Head |
|---|---|---|
| Head 数量 | 2 | 1 |
| 动作维度 | 180 (=3×10×3×2) | 90 (=3×10×3) |
| 速度约束 | `v_fd` + `v_net` 融合 → clip | 积分后 clip |
| 加速度约束 | FD 加速度 → 倾角 → clip | 直接约束加速度 |
| 位置边界 | clamp arena | clamp arena |
| 物理一致性 | 显式调和 pos↔vel | 天然一致（积分） |
| 语义可解释性 | 高（位置=去哪，速度=多快） | 中（加速度=推多少） |
| 实现复杂度 | 中 | 低 |
| PPO 训练难度 | 中（双 Head log_prob 联合分布） | 低（单 Head） |
| 推荐优先级 | ★★★ 推荐 | ★★ 备选 |

**建议先实现方案 B（Acceleration Head）快速验证训练链路，再迁移到方案 A（Pos+Vel）以获得更好的可解释性和控制精度。**

## 11. 单元测试要求

需验证：

1. **位置范围**：投影后所有 xy 在 arena 半径内，z 在 [z_min, z_max]
2. **速度上限**：投影后 ‖v‖ ≤ v_max
3. **加速度上限**：投影后 ‖a‖ ≤ a_max
4. **倾角满足**：投影后 ‖a_xy‖ ≤ (9.81 + a_z) · tan(θ_max)

   - 掉前 2 步后长度 = H
   - mask 前 H-2 步 = 1，后 2 步 = 0
   - mask=0 部分改变值不影响输出
7. **排列等变性**：交换 agent 0/1，轨迹相应交换
8. **与现有控制器兼容**：`_acceleration_to_pidrate_action` 输出 `[-1,1]`，无 NaN
